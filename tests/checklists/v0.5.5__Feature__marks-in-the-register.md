# Human Test Checklist: the marks in the register (format v3)

**Target version:** 0.5.5
**Ships with commit:** `feat(register): the marks move into the file as slots, format v3 (v0.5.5)`
**Companion automated tests:** 337 core tests under `tests/core/` (`register-ops.test.ts` 13, `migrations.test.ts` 8 among them) and 90 kit tests under `plugin/tests/` (`migration.test.ts` 5, `delmarks.test.ts` 2, `palette.test.ts` 3), run with `node --test tests/core/*.test.ts` and `claude plugin test plugin`.

## What this is

The letters (`a`-`z`) and the reading position used to live in Claude Code's plugin store; from 0.5.5 they are records in the conversation's bookmark file, each letter a slot with a history. This checklist is for what the tests cannot touch: a real folder migrated from a real store, the marks you actually had, and the panes as you use them. Run it after `v0.5.4__Feature__register-format-v2-and-the-migration.md`, or on its own on a machine that was at 0.5.4.

## Prerequisites

1. Claude Code 2.1.288 or later, the plugin at 0.5.5 or later (`/bm-env`), the fullscreen renderer.
2. Before upgrading, note which letters you had in a conversation (`Ctrl+] '` lists them) and whether a reading position was set. If you already upgraded, the run folder under `~/claude/bookmarks/backups/*__v2-to-v3__*/store/<id>.json` holds what the store had.
3. A copy of your data folder, as in the v0.5.4 checklist's prerequisites.

**Reset between sections:** none needed; every section marks and reads. To rerun the migration, restore the folder from your copy and delete `backups/`.

## High-Value Verification (~5 minutes)

### HV.1 -- Every letter you had is still there

Validates: the v2 -> v3 migration moved the store's marks into the file.

- [ ] **Steps:** start Claude Code in a conversation that had letters; `Ctrl+] '`.
- [ ] **Expected:** the jump pane lists the same letters as before, with the same heads; `Ctrl+] '` then a letter jumps as before. In the file, each letter is under `"slots": { "user": { "a": { "current": N, "history": [...] } } }` and `N` is a record with `"tier": "mark"`.
- [ ] **Why this matters:** a letter lost here is a mark the person set and cannot get back from the store, which the migration emptied (the run folder still has it).

### HV.2 -- Re-marking a letter keeps the old place

Validates: the `a_001` stack.

- [ ] **Steps:** `Ctrl+] m a` on one line; scroll elsewhere; `Ctrl+] m a` on another line. Open the file.
- [ ] **Expected:** `slots.user.a.history` has two entries, the newer first; `current` is the newer's `n`; both records are in `perma` with `"tier": "mark"`. `Ctrl+] ' a` goes to the newer place.
- [ ] **Why this matters:** this is the promise of #10 that a re-mark never throws the old spot away.

### HV.3 -- Deleting a mark clears the letter and keeps its history

Validates: the cleared state (the delete gesture's first verb).

- [ ] **Steps:** `/bm-delmarks a`. Then `Ctrl+] '`.
- [ ] **Expected:** the toast says `deleted mark a`; `a` is gone from the jump pane; in the file `slots.user.a.current` is `null` and `history` is unchanged; the records stay. `Ctrl+] m a` on a new line afterwards works, and the history grows by one.
- [ ] **Why this matters:** a cleared letter that erased its history would make `/bm-delmarks all` a data loss.

### HV.4 -- The reading position is a slot too

Validates: the reading key (`` ` ``) in the same mechanism.

- [ ] **Steps:** select a line, `Ctrl+] Space Space` to set the reading position; scroll away; `Ctrl+] Space Space` again.
- [ ] **Expected:** you return to the line, as before. In the file, `slots.user` has a `` ` `` key whose current record has the selected words as `words`.
- [ ] **Why this matters:** the reading position is the mark people use most; it must survive the move.

## Section 1: the panes read memory (~3 minutes)

### 1.1 Marks show while another window writes

- [ ] **Steps:** open the same conversation in a second Claude Code window (or edit the file's `slots` by hand: change a `current` to another `n` in the history). In the first window, `Ctrl+] '`.
- [ ] **Expected:** the first window shows its own view until its next mark write or start; after `Ctrl+] m b` there, the file holds both the hand edit and the new `b` (the operation replayed onto the changed file; debug log: `changed on disk ... applied to the disk's version`).

### 1.2 A bookmark and a mark on the same line are two things

- [ ] **Steps:** `Ctrl+] m c` on a line that is also a bookmark (or bookmark a marked line with `/bm-promote c`).
- [ ] **Expected:** the bookmarks pane shows the bookmark with its label; the mark pane shows `c`; neither renames the other; the file has two records for the message, one `"tier": "mark"`.

## What the automated tests DON'T cover

- A real store with marks from 0.4.x builds (fields and ids as they were then).
- The jump itself after a migration (the kit has no scroll).
- Two live windows on one file.
- The fallback without a data folder (`CLAUDE_USER_DIR` unset and no `~/claude`): marks in the store as before.
- How the mark pane looks with a long history (no UI for the history yet: `a_001` is in the file only).

## Reporting issues found

1. Note the section and step number.
2. Attach the conversation's debug log and the `__v2-to-v3__` run folder's `manifest.json` and `store/<id>.json`.
3. File an issue at https://github.com/DazzleML/claude-bookmarks/issues referencing this checklist and the version.
