# Human Test Checklist: Bookmark anchors (v0.2.0)

**Target version:** 0.2.0
**Ships with commit:** v0.2.0: bookmarks, Claude's bookmark tool, clickable anchors (TBD at commit)
**Companion automated tests:** 32 tests in `hooks/core/anchor.test.ts` (13), `hooks/core/transcript-lines.test.ts` (9), `hooks/core/register-file.test.ts` (10), run with `node --test hooks/core/anchor.test.ts hooks/core/transcript-lines.test.ts hooks/core/register-file.test.ts` (Node 22+). `claude plugin validate .` must pass.

## What this is

v0.2.0 adds bookmarks: permanent, addressable places in a conversation, kept as readable files under the person's own folder. Claude mints them with a tool and cites them as links in its replies; a click jumps there; the person promotes marks into bookmarks, browses two lists, and goes back and forward over jumps. Everything that happens on screen (clicks, highlights, panes, keys), everything that touches the real transcript and the real data folder, and everything the terminal does with a link is beyond the automated tests, which cover only the pure modules (URL format, transcript resolver, register file). This checklist is what a person runs in a live Claude Code session before the version ships. Run it in a fresh conversation started from a shell (`claude`), not a background or daemon-hosted session.

## Prerequisites

1. Claude Code 2.1.295 or later, **fullscreen renderer** (`"tui": "fullscreen"` in settings), Windows Terminal or another terminal that reports clicks and draws hyperlinks. The plugin loaded from a working copy (`--plugin-dir` or `CLAUDE_CODE_PLUGIN_DIRS`), and `Ctrl+]` bound to `abovePrompt:focus` (see README, "Set up the leader").
2. **Isolate the data folder** so the run never touches your real bookmarks. The plugin writes under `CLAUDE_USER_DIR` when set, else `~/claude`. Set it to a scratch folder before starting Claude Code:

   **cmd.exe**:
   ```cmd
   set CLAUDE_USER_DIR=%TEMP%\bm-checklist
   mkdir %TEMP%\bm-checklist
   claude
   ```

   **PowerShell**:
   ```powershell
   $env:CLAUDE_USER_DIR = "$env:TEMP\bm-checklist"
   New-Item -ItemType Directory -Force $env:CLAUDE_USER_DIR | Out-Null
   claude
   ```

   **POSIX**:
   ```bash
   export CLAUDE_USER_DIR=/tmp/bm-checklist
   mkdir -p "$CLAUDE_USER_DIR"
   claude
   ```

3. In that session, type three or four prompts so the conversation has something to bookmark (one of them should contain a distinctive phrase, e.g. "the quick brown bookmark"), and let Claude answer each.
4. Run `/bm-env` once; note the session id it prints (`<sid>` below) and the dcc-patcher line.
5. **Reset between sections:** delete the scratch register and exports (`<CLAUDE_USER_DIR>/bookmarks/sessions/<sid>.json`, `.json.bak`, and the `<sid>/` folder) and run `/bm-delmarks all`. The plugin recreates them on the next mint.

## High-Value Verification (~5 minutes)

**If you only have 5 minutes**, run these six. They are the "did the work ship" tests.

### HV.1 — Claude mints a bookmark and the link jumps

Validates: the tool, the resolver, the register write, the link in the reply, the click, the arrival highlight.

- [ ] **Steps:**
  1. Ask: `Bookmark the message where I said "the quick brown bookmark" and link it in your reply.`
  2. Claude's reply contains a link drawn with a `⚓` marker and a dim legend line under the reply.
  3. Scroll elsewhere, then **plain-click** the link.
- [ ] **Expected:** the view jumps to your message; the words "the quick brown bookmark" are drawn on a coloured line, bold, with an `«@»` tag; a dim log line (only if `/bm-debug on`) says `anchor press scroll -> ok`.
- [ ] **Why this matters:** this is the feature. If the click does not jump, nothing else here is worth running.

### HV.2 — Ctrl-click opens the bookmark's file

Validates: the export file and the URL form Windows accepts (query string, no fragment).

- [ ] **Steps:** ctrl-click the same link.
- [ ] **Expected:** `<CLAUDE_USER_DIR>/bookmarks/sessions/<sid>/<uuid8>.md` opens in your default markdown application, showing front matter (session, uuid, owners, line, bytes, words, label), the quoted message with the words in bold, a "Verify by hand" recipe and a Notes section.
- [ ] **Why this matters:** the file is the bookmark's durable form and the ctrl-click is the only way to it from the terminal.

### HV.3 — The register is readable JSON under the data root, not under `~/.claude`

Validates: storage rules (#6, #21).

- [ ] **Steps** (pick your shell):

  **cmd.exe**: `type %CLAUDE_USER_DIR%\bookmarks\sessions\<sid>.json`
  **PowerShell**: `Get-Content $env:CLAUDE_USER_DIR\bookmarks\sessions\<sid>.json`
  **POSIX**: `cat "$CLAUDE_USER_DIR/bookmarks/sessions/<sid>.json"`
- [ ] **Expected:** pretty JSON with `version`, `sessionId`, `rev`, `perma: [ { sessionId, uuid, owner: "claude", label, ... } ]`, `tombstones: []`; nothing was written under `~/.claude/` for it.
- [ ] **Why this matters:** bookmarks must survive Claude Code's housekeeping and be hand-readable.

### HV.4 — Two lists, and promotion

Validates: owner separation, `Ctrl+] P`, the pane's groups.

- [ ] **Steps:**
  1. Select a line in any message, `Ctrl+]` `m` `a` (mark `a`).
  2. `Ctrl+]` `P` `a`.
  3. `Ctrl+]` `b`.
- [ ] **Expected:** step 2 toasts "bookmarked: …(link copied)"; the clipboard holds a markdown link. Step 3 opens the pane on `[yours 1]  Claude's 1  all 2` with your promoted bookmark listed; `l` shows Claude's; `l` again shows all; `h` goes back. Mark `a` still exists (`/bm-marks`).
- [ ] **Why this matters:** Claude's citations must never land on the person's list, and the person's marks must be promotable without being changed.

### HV.5 — Back and forward

Validates: the jumplist and that the reading position is untouched.

- [ ] **Steps:** after HV.1's jump, `Ctrl+]` `o`; then `Ctrl+]` `i`.
- [ ] **Expected:** `o` returns to the reply you clicked from (toast "back: …"); `i` goes to the bookmark again (toast "forward: …"). `Ctrl+] Space Space` still goes to the reading position you set, if any, unaffected.
- [ ] **Why this matters:** a jump you can't come back from is a trap.

### HV.6 — Narrow terminal: the pane still draws

Validates: the attribution fix (the band's field returns its promise).

- [ ] **Steps:** shrink the terminal to about 100 columns (a half-screen window), then `Ctrl+]` `p`.
- [ ] **Expected:** the prompts pane is drawn (docked or inline) and the conversation returns to where it was. Before v0.2.0 nothing appeared below about 110 columns. If the terminal is narrower than the engine allows at all, a toast says why.
- [ ] **Why this matters:** the fix for the morning's original bug; regressing it makes every band command silent on small screens.

## Section 1: Minting with the tool (~5 min)

### 1.1 Ambiguous fragment returns candidates, never guesses

- [ ] **Steps:** send the same distinctive phrase in two different prompts, then ask Claude to bookmark "the message with the quick brown bookmark".
- [ ] **Expected:** Claude reports the tool's answer: ambiguous, with the earliest message named and candidates listed; it either asks or picks the earliest and says so. No bookmark is minted until a single message is chosen (by uuid or a longer fragment).

### 1.2 A fragment that occurs nowhere

- [ ] **Steps:** ask Claude to bookmark "a phrase that was never said in this conversation".
- [ ] **Expected:** the tool answers `error: no match` with a hint; nothing is written to the register.

### 1.3 Relabel does not duplicate

- [ ] **Steps:** ask Claude to bookmark the same message again with a different label.
- [ ] **Expected:** the register still has one record for that uuid on Claude's list, with the new label and a bumped `rev`; the export's title changed; `.json.bak` holds the previous version.

### 1.4 `owner: user`, share, remove, list

- [ ] **Steps:** ask Claude: (a) "bookmark my second prompt for me" (it should use `owner: user`), (b) "share your bookmark of the quick brown bookmark onto my list", (c) "remove the bookmark of my second prompt from my list", (d) "list the bookmarks".
- [ ] **Expected:** (a) lands under "yours"; (b) a copy appears under "yours" with `sharedFrom: claude`, Claude's record stays; (c) the record leaves "yours" and a tombstone with `removedBy` appears in the JSON; (d) both lists are returned with their links.

### 1.5 Temporary bookmarks

- [ ] **Steps:** ask Claude to bookmark a message "temporarily". Inspect the register.
- [ ] **Expected:** the record has `temporary: true` and the pane shows "temporary" in its provenance line. (Pruning after 30 days can't be exercised here; the pure test covers `prune()`.)

### 1.6 The notes section survives a relabel

- [ ] **Steps:** open the export (HV.2), write a line under `## Notes`, save; ask Claude to relabel that bookmark; reopen the export.
- [ ] **Expected:** the title changed; your note is still there, unchanged.

## Section 2: Links in replies (~5 min)

### 2.1 Markers and legend

- [ ] **Steps:** ask Claude to cite one bookmark and one file (e.g. "link me to docs/usage.md too").
- [ ] **Expected:** the bookmark link has `⚓`, the file link `▤`, the legend mentions both; a plain web link in the same reply has no marker.

### 2.2 A hand-written anchor link becomes a bookmark

- [ ] **Steps:** copy a bookmark's URL from the register, change nothing, and ask Claude to "paste this link in your reply, as a markdown link labelled hand-written: `<url>`". Then `/bm-bookmarks`.
- [ ] **Expected:** the link is clickable and jumps; within a second of the reply drawing, a record with `by: prose` exists for it (if it was not already on Claude's list).

### 2.3 A malformed anchor is harmless

- [ ] **Steps:** ask Claude to write a markdown link whose URL is `file:///C:/nowhere/bookmarks/sessions/x/deadbeef.md?u=not-a-uuid`.
- [ ] **Expected:** drawn as an ordinary link, no marker, no jump on plain click, nothing recorded.

### 2.4 A mark on a reply that carries links

- [ ] **Steps:** select a line in a reply that contains a `⚓` link, `Ctrl+] m` `b`, scroll away, `Ctrl+] '` `b`.
- [ ] **Expected:** the view returns and the marked line is drawn in colour (band and yellow words) as on any other message; the reply's links still work.

### 2.5 Refused jump (resumed session on stock Claude Code)

- [ ] **Steps:** exit the session, `claude --resume <sid>`, click a bookmark link to a message from before the last compaction (if the session has one).
- [ ] **Expected:** on stock Claude Code the jump is refused with the clipboard toast (the bookmark's words copied, `Ctrl+O` `[` Find instructions); on a build with dcc-patcher's history patch (`/bm-env` shows `DCC_PATCH_H=history-v1`) it jumps. Skip if the session never compacted.

## Section 3: The pane and the band (~5 min)

### 3.1 Number entry

- [ ] **Steps:** `Ctrl+] b`, then type a bookmark's number and `Enter`.
- [ ] **Expected:** the `#` field shows the digits, the `▶` moves to that row, `Enter` jumps and highlights the words, the pane closes.

### 3.2 `j`/`k` browse and `Esc`

- [ ] **Steps:** `Ctrl+] b`, `j`, `j`, `k`, `Esc`.
- [ ] **Expected:** the `▶` moves down, down, up; `Esc` closes without jumping and the keyboard returns to the input box.

### 3.3 Empty group

- [ ] **Steps:** with no promoted bookmarks, `Ctrl+] b`.
- [ ] **Expected:** `[yours 0]` with "No bookmarks in "yours" yet."; `l` shows Claude's.

### 3.4 `/bm-bookmarks` from an empty input box

- [ ] **Expected:** the pane takes the keyboard itself; `Tab` walks the rows; `Enter` jumps.

### 3.5 The log echo is off by default

- [ ] **Steps:** start a second session in another folder with the plugin loaded; do nothing.
- [ ] **Expected:** no `convo-bookmarks:` dim lines appear on start-up. `/bm-debug status` says "log echo is off"; `/bm-debug on` makes the next actions echo; `/bm-debug off` silences them again. The file log under `<CLAUDE_USER_DIR>/bookmarks/debug/` is written either way.
- Note: in v0.2.0 the switch is one setting shared by every conversation; v0.2.1 makes it per conversation (see `v0.2.1__Feature__debug-echo-per-conversation.md`).

### 3.6 `/bm-env`

- [ ] **Expected:** two lines: the plugin and Claude Code versions with the session id, and `dcc-patcher: … DCC_PATCH_H=… DCC_PATCHES=…` (all `(unset)` / "none seen" on stock).

## Section 4: Direct keys from the band (~2 min)

### 4.1 `'a` jumps without an Enter probe

- [ ] **Steps:** with mark `a` set, `Ctrl+]` `'` `a`.
- [ ] **Expected:** the jump happens at once with the highlight; no "Press Enter to jump" toast (removed in v0.2.0).

### 4.2 `Space` from the field

- [ ] **Steps:** with a reading position set, `Ctrl+]` `Space`.
- [ ] **Expected:** goes to the reading position (or back), as `Space Space` did before.

## What the automated tests DO cover

| Area | Test file | Count |
|---|---|---|
| Anchor URL format, parse (query and legacy fragment), moved data root, a data root with `( ) ? #` in it, uuid cross-check, link finding outside code, markers, position grammar, UTF-8 byte length | `hooks/core/anchor.test.ts` | 13 |
| grep-line parsing (incl. CRLF from the process runner), message-row selection (user, assistant, mid-turn `queued_command` attachments; bookkeeping rows dropped), byte ranges tiling the file, earliest-match and candidates, uuid prefix | `hooks/core/transcript-lines.test.ts` | 9 |
| Register add/relabel (never duplicate, never delete), two lists, share, remove with tombstone, temporary prune with tombstones, stable JSON order and round trip, `.bak` precedence helper, export front matter and notes surviving a rewrite (one heading and one marker however often it is rewritten), bold words (also with `$` in them) and long-message jump link | `hooks/core/register-file.test.ts` | 10 |
| Exploratory tests from the pre-release sweep: unusual data roots, nested brackets, fences, `parsePosition` edge cases, same-prefix uuids, prune at the boundary, YAML quoting; the transcript resolver on a real 4 MB transcript (`resolver-real-transcript.mjs`, byte ranges checked against `head | wc -c`) | `tests/one-offs/thinking/anchors/` | 37 |

Red-green audit (2026-10-09): 6 anchors (CRLF byte count, mid-turn rows, notes survive rewrite, data root with `( ) ? #`, `$` in the bookmarked words, a note that quotes the marker), 26 guards. The pre-release sweep found four defects in the pure modules (a `)` or `?` in the data root broke the link, `$&` in the words corrupted the export, a quoted marker grew the export on every rewrite) and one it exposed (the `## Notes` heading doubled on every relabel); all five are fixed and anchored.

## What the automated tests DON'T cover

- Everything in `hooks/register.tsx`: the tool registration and call, the render hook that makes links pressable, the click and the engine's "person's input" rule, the pane, the band keys, the jumplist, promotion, the file I/O against the real data root and the real transcript.
- The terminal: whether a `file:` link opens, in which application, and that a `#` fragment would not.
- Colours and the `⚓` glyph on your terminal font; the pane's layout at narrow widths.
- The 30-day prune of temporary bookmarks (only the pure function is tested).
- A resumed session on stock Claude Code vs the patched build (Section 2.5).
- macOS and Linux (Section 5).

## Reporting issues found

1. Note the section and step number.
2. Run `/bm-debug on`, repeat the step, and copy the dim log lines (or the matching lines from `<CLAUDE_USER_DIR>/bookmarks/debug/<sid>.log`).
3. Attach the register JSON and the export if the step touched them.
4. File an issue on DazzleML/claude-bookmarks referencing this checklist and v0.2.0.

## Cleanup

1. `/bm-delmarks all` in the test session; exit it.
2. Delete the scratch folder:

   **cmd.exe**: `rmdir /s /q %TEMP%\bm-checklist`
   **PowerShell**: `Remove-Item -Recurse -Force $env:TEMP\bm-checklist`
   **POSIX**: `rm -rf /tmp/bm-checklist`

3. Unset the variable so your next session uses your real folder:

   **cmd.exe**: `set CLAUDE_USER_DIR=`
   **PowerShell**: `Remove-Item Env:\CLAUDE_USER_DIR`
   **POSIX**: `unset CLAUDE_USER_DIR`
