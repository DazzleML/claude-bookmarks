## What this is

The live looks the automated tests cannot take: Claude Code's own `/config` screen, a real scroll with the prompts pane open, the debug log on disk, and how the band and the marked line look. The kit tests already prove that `/config` values reach the plugin, that a change takes effect, and that the text setting decides which log lines are kept.

## Prerequisites

1. Claude Code 2.1.287 or later, started from a shell with the plugin loaded from this working tree (`claude --plugin-dir <repo>/plugin`), in a conversation with a dozen prompts or more.
2. Note your current `/config` values for the plugin before changing any; the last section restores them.
3. The debug log is `<user dir>/bookmarks/debug/<session id>.log`, where `<user dir>` is `CLAUDE_USER_DIR` or `~/claude`; `/bm-env` shows the session id. To read its last lines:

   **cmd.exe**: `powershell -Command "Get-Content $env:USERPROFILE\claude\bookmarks\debug\<session id>.log -Tail 20"`
   **PowerShell**: `Get-Content "$env:USERPROFILE\claude\bookmarks\debug\<session id>.log" -Tail 20`
   **POSIX**: `tail -20 ~/claude/bookmarks/debug/<session id>.log`

## High-Value Verification (~5 minutes)

### HV.1 — The settings appear in /config

- [ ] **Steps:** type `/config`, find the plugin's section.
- [ ] **Expected:** nine fields under the plugin's name: "Prompts list opens at", "Prompts list follows the view", "Closeness for the earlier prompt" (a number), "A list after a jump", "A list while you type", "Keyboard after an action", "Debug echo by default", "Conversation text in the debug log", "How much text a debug line quotes". Each picker shows its default (`nearest`, `when-idle`, `close`, `stay`, `input`, `off`, `auto`, `reference`).
- [ ] **Why this matters:** if `/config` does not show them, no person can change a setting.

### HV.2 — A change takes effect, and whether it reloads the plugin

- [ ] **Steps:** set "Prompts list follows the view" to `never`; leave `/config`; type `/bm-config`; open the prompts list (`Ctrl+] p`) and scroll the conversation with the mouse.
- [ ] **Expected:** `/bm-config` shows `followHere="never" (/config)`; the list no longer scrolls to keep the yellow row showing.
- [ ] **Record:** in the debug log's last lines, did the change reload the plugin (a fresh start-up line such as `[bm] tool registered` right after the change)? Write yes or no here: ____
- [ ] **Why this matters:** the plugin keeps settings current from Claude Code's change event; this confirms it on a real build and answers whether a change reloads.

### HV.3 — The list opens at the newest prompt when asked

- [ ] **Steps:** set "Prompts list opens at" to `newest`; scroll the conversation up several screens; `Ctrl+] p`.
- [ ] **Expected:** the list opens at its top, the newest prompt, not centred on the prompt nearest your view. Set it back to `nearest` and repeat: the list centres on the nearest prompt again.
- [ ] **Why this matters:** the first setting a person is likely to change.

### HV.4 — Conversation text in the debug log

- [ ] **Steps:**
  1. `/bm-config`: the second line says `this build is loaded from a folder, so debugText="auto" means always`.
  2. Select a few words in a reply and set a mark (`Ctrl+] m a`). Read the log's last lines.
  3. Set "Conversation text in the debug log" to `off`; set mark `b` the same way; read the log.
  4. `/bm-debug enable text`; set mark `c`; read the log. `/bm-debug disable text`.
  5. Set "How much text a debug line quotes" to `full`, the text setting back to `auto`; select a long passage and set mark `d`.
- [ ] **Expected:** step 2's `[bm] mark a -> ...` and `selection "..."` lines quote the words; step 3 has no line quoting the words for `b`; step 4 quotes them again; step 5's `selection` line carries the whole selection, not the first 24 characters.
- [ ] **Why this matters:** a developer's build keeps everything for debugging; an installed one quotes nothing unless the person asks.

### HV.5 — Nothing else moved

- [ ] **Steps:** with every setting at its default: `Ctrl+] p`, type `3`, `Enter`; `Ctrl+] p`, `j`, `k`, `s`, `Esc`; set a mark on a prompt and on a reply (`Ctrl+] m a`, `Ctrl+] m b`) and look at them.
- [ ] **Expected:** the band and the prompts list behave as in 0.4.16; the marked line keeps its soft band and the bold yellow letter and words on both.
- [ ] **Why this matters:** settings now read where constants were.

## What the automated tests DON'T cover

- Claude Code's real `/config` screen and its pickers
- Whether a change in `/config` reloads the plugin
- A real scroll with the pane open (`followHere`) and where the list really opens (`listOpensAt`)
- The debug log on a real disk, and an installed (marketplace) build's `auto`
- How the band and the marked line look

## Reporting issues found

Note the step, copy the debug log's last lines and `/bm-config`'s output, and file an issue referencing this checklist and 0.4.17.

## Cleanup

Set every field you changed back to what you noted in Prerequisites step 2 (`/config`), and run `/bm-debug disable text` if step HV.4.4 was interrupted.
