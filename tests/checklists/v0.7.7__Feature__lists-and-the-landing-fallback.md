# Human Test Checklist: lists, and the landing fallback

**Target version:** 0.7.7 (lists), with 0.7.6 (the landing fallback, `46afbe9`) checked here too
**Ships with commit:** `feat(lists): named, ordered lists per project, in a pane beside the conversation (v0.7.7)`
**Companion automated tests:** `tests/core/lists.test.ts` (10: the file name, create/add/move/remove/done/delete/share, ids never reused, the file read back, a newer file refused, the page), `tests/core/landing.test.ts` (+7: where a record lands when Claude Code draws nothing under its id), `plugin/tests/lists.test.ts` (6: `/bm-lists` opens the docked pane, the pane draws the file, a press reorders and ticks and writes the file and page, a link is copied, the tool creates and fills a list, the tool's refusals). Red-green: 9 deliberate breaks of the lists code and 6 of the landing fallback, all caught.

## What this is

A short hand check of two things: the new lists pane (named, ordered lists kept per project, with Claude's `lists` tool to fill them), and the fix that lets a link to a tool row land when Claude Code draws no row under that tool's id. The kit shows what the pane returns, not where the engine seats it, whether it stays up while you type, or how a real refused scroll behaves, so those are checked here, live.

## Prerequisites

1. **Reload the plugin, or start or resume a session.** `/bm-lists` and the `lists` tool are registered when the plugin starts; a hot reload of its code does not register them.
2. **Fullscreen, 110 columns or wider**, for the pane to dock on the right. Narrower, it opens inline above the prompt.
3. The pane reads the lists of the folder Claude Code runs in. For the maintainer's session in `dazzle-claude-plugins`, a first list, "What's left", was seeded at `~/claude/bookmarks/lists/dazzle-claude-plugins.json`. In any other folder the pane starts empty; HV.5 makes a list.
4. Back up the lists file before the reordering steps if you want its order back afterwards:

   **cmd.exe**: `copy %USERPROFILE%\claude\bookmarks\lists\dazzle-claude-plugins.json %TEMP%\lists-before.json`
   **PowerShell**: `Copy-Item "$env:USERPROFILE\claude\bookmarks\lists\dazzle-claude-plugins.json" "$env:TEMP\lists-before.json"`
   **POSIX**: `cp ~/claude/bookmarks/lists/dazzle-claude-plugins.json /tmp/lists-before.json`

## High-Value Verification (~5 minutes)

### HV.1: the pane docks beside the conversation, without the keyboard

- [ ] **Steps:** type `/bm-lists`; then type a few characters into the input box.
- [ ] **Expected:** a pane titled Lists docks on the right (its own tab if the prompts or search pane is open too). The top row reads `▸What's left (9)`; below, nine numbered items, each with `▲ ▼ ·` on its right, a `⚓` before the ones that are places and `▤` before the links. Your typing goes to the input box; the pane stays up.
- [ ] **Why this matters:** a list you can keep in view while you work is the point of the feature.

### HV.2: a tool row with no drawn id still lands, with one message

- [ ] **Steps:** press item 2, "Commit the landing fix" (it points at an `AskUserQuestion` row).
- [ ] **Expected:** the view goes to the reply that question was asked in, and **one** toast says Claude Code draws no row of its own for that call. Not two toasts, and no "can't jump there".
- [ ] **Why this matters:** before the fix this link was refused ("nothing drawn under that requestId").

### HV.3: reordering sticks

- [ ] **Steps:** press `▼` on item 1, then `▲` on what is now item 2; close the pane (`/bm-lists`) and open it again.
- [ ] **Expected:** the first press swaps items 1 and 2, the second swaps them back, and the order survives the close. `lists/dazzle-claude-plugins.json` and `.md` have changed, and `.json.bak` exists beside them.

### HV.4: ticking done

- [ ] **Steps:** press `·` on any item; press its `✓` again.
- [ ] **Expected:** it turns to `✓`, the item dims, and the count in the tab drops by one; the second press restores it.

### HV.5: Claude keeps a list for you

- [ ] **Steps:** ask Claude: "make me a list called Tests to run, with two items".
- [ ] **Expected:** Claude finds its `lists` tool (it is loaded only when needed), and the pane gains a `Tests to run (2)` tab with the two items. Press the tab to show it.

### HV.6: a link item

- [ ] **Steps:** press item 4 (a GitHub issue link); then ctrl-click it, and ctrl-click an item that points at a file.
- [ ] **Expected:** the press copies the URL with a toast; the ctrl-click opens the page in the browser, and the file in its default program, as links in Claude's replies do.

## What the automated tests DON'T cover

- Where the engine actually seats the pane, and how wide; the kit answers every open "placed".
- Whether a pane opened without the keyboard stays up while you type, and sits as a second tab beside the prompts pane.
- Whether the deferred `lists` tool is found when Claude needs it.
- A real "nothing drawn" refusal from Claude Code; the kit fakes the scroll.
- How the item rows wrap in a narrow dock.

## Reporting issues found

Note the HV number, what the pane drew (a paste or a screenshot), and the plugin's log lines starting `[bm] lists` or `[bm] list item`.
