## High-Value Verification (~5 minutes)

### HV.1 — The bar reads once, and each word is clickable

- [ ] **Steps:** look at the band at rest; click each word.
- [ ] **Expected:** `bm: _  m: mark  j: jump  p: prompts  r: read  ?` (Claude Code draws a button's hotkey before its label), nothing listed twice and no bare letters; `mark` opens the mark pane, `jump` the jump pane, `prompts` the prompts list, `read` goes to the reading position, `?` shows the help.
- [ ] **Why this matters:** #29's first criterion: "The idle band shows each key once, explained, and clickable".

### HV.2 — `?` after the leader

- [ ] **Steps:** `Ctrl+] ?`; read the help; press `Enter`. Again `Ctrl+] ?`, then `Esc`.
- [ ] **Expected:** the band grows to the help (every command with its keys, the list keys, `Chords ...: on. Lists in a pane: on`); `Enter` returns to the bar; after `Esc` the help goes within a second and the keyboard is in the input box.

### HV.3 — Keys and clicks agree

- [ ] **Steps:** `Ctrl+] p` then `Esc`; then click `prompts`. `Ctrl+] r`; then click `read`.
- [ ] **Expected:** each pair does the same thing (the typed key leaves the band holding the keys; a click opens the pane as a list to click).

### HV.4 — Chords off

- [ ] **Steps:** with a chord bound (e.g. `ctrl+x space` to `app:diffFileListDown`), press it: it goes to the reading position. `/config` -> "Chords on their own keybindings" -> `off`; press it again.
- [ ] **Expected:** with `off` the chord does nothing (or what Claude Code does with it), and the leader still works. Set it back to `on`.

### HV.5 — The band as a field only

- [ ] **Steps:** `/config` -> "The band" -> `field`.
- [ ] **Expected:** the band is `bm: _` alone; `Ctrl+] m`, `Ctrl+] ?` still work. Set it back to `full`.

### HV.6 — Lists off

- [ ] **Steps:** `/config` -> "Lists in a pane" -> `off`; `Ctrl+] p`, type a number, `Enter`; `Ctrl+] m a`; `Ctrl+] ' a`.
- [ ] **Expected:** no pane opens; the band shows `prompt #` with the digits and jumps on `Enter`; the mark and jump take their letter in the band. Set it back to `on`.

### HV.7 — The help, by click and by keyboard (0.4.26)

- [ ] **Steps:** click `?`; then `Ctrl+] ?` and press the Up and Down arrows; then `Esc`. Repeat in a short terminal (a few rows above the prompt).
- [ ] **Expected:** a click keeps the help until `close` (passed 2026-10-12: it stays, and the mouse wheel scrolls it). By keyboard the help fits the band, so nothing jumps back to the top; in a short band it is the four-line form. `Esc` ends it within about half a second.

### HV.8 — The bookmarks list is not all dim (0.4.41)

Validates: the bookmarks pane dims a row only when its message has not been drawn since the plugin loaded, by the same rule as the prompts pane.

- [ ] **Steps:**
  1. In a conversation with at least two bookmarks whose messages are on screen or were scrolled past since the plugin loaded, press the leader, then `b`.
  2. Scroll the conversation so one bookmarked message has never been drawn in this session (an old one, before the plugin loaded), and open the list again.
- [ ] **Expected:** rows for drawn messages are at full strength; only the never-drawn message's row is dim. Before 0.4.41 every row was dim except the one the band's number pointed at.
- [ ] **Why this matters:** the dim hint is the one cue that a jump may be refused; when every row is dim it says nothing.

### HV.9 — A new conversation has its own bookmarks (0.4.65)

Validates: after `/clear` (or `/resume` of another conversation) in the same Claude Code process, the bookmarks list and the `bookmark` tool see the new conversation's register, not the one before.

- [ ] **Steps:**
  1. In a conversation with at least one bookmark, press the leader, then `b`: note the rows.
  2. Run `/clear`. Press the leader, then `b` again.
  3. Ask Claude to bookmark something in the new conversation, then look in `<dataRoot>/bookmarks/sessions/`.
- [ ] **Expected:** after `/clear` the list is empty (the new conversation has no bookmarks yet). The new bookmark lands in a file named for the new session id, holding only that bookmark. The earlier conversation's file is unchanged.
- [ ] **Why this matters:** before 0.4.65 the register stayed in memory across the boundary, so the new conversation listed the old bookmarks, and its first save wrote them under the new conversation's name.

### HV.10 — A new conversation has its own back and forward (0.4.72)

Validates: after `/clear` (or `/resume` of another conversation) in the same Claude Code process, `<leader> o` and `<leader> i` walk the new conversation's jumps, not the previous one's.

- [ ] **Steps:**
  1. In a conversation, make two or three jumps (a mark, a prompts-pane row, a bookmark), then press the leader and `o` once: it goes back.
  2. Run `/clear`. Press the leader, then `o`.
  3. `/resume` the first conversation. Press the leader, then `o`.
- [ ] **Expected:** after `/clear`, the toast says "Nothing to go back to" and the view does not move. After `/resume`, `o` walks the first conversation's own jumps, as they were before `/clear`.
- [ ] **Why this matters:** before 0.4.72 the jumplist stayed in memory across the boundary: the new conversation's `o` tried to go to the old conversation's messages, and its next jump wrote the old list over the new conversation's.

### HV.11 — Nothing of the old conversation lingers after `/clear` (0.4.73)

Validates: a highlight, a pane's remembered place, a mark chord's selection and the prompts pane's yellow row do not carry from one conversation into the next.

- [ ] **Steps:**
  1. Jump to a mark so its line is highlighted; with the highlight showing, run `/clear`.
  2. In a conversation, press the leader then `m` with text selected, but press Esc instead of a letter; run `/clear`; after a reply or two, press the leader, `m`, then a letter with nothing selected.
  3. With the prompts pane open, run `/clear`; send a prompt or two and open the prompts pane again.
- [ ] **Expected:** (1) the highlight is gone after `/clear`. (2) The mark lands on the message at the top of the new conversation's screen, not on the selection from before `/clear`. (3) The yellow row, if any, is one of the new conversation's prompts.
- [ ] **Why this matters:** before 0.4.73 these were held in memory across the boundary; the worst case stored a mark in the new conversation pointing at a message of the old one.

### HV.12 — Each conversation has its own debug log (0.4.74)

Validates: after `/clear` (or `/resume`), the plugin's log lines go to the new conversation's file under `<dataRoot>/bookmarks/debug/`.

- [ ] **Steps:**
  1. Run `/bm-debug status` and note the log path (it ends in this conversation's session id).
  2. Run `/clear`, then `/bm-debug status` again, and do something that logs (open the prompts pane).
  3. Look in `<dataRoot>/bookmarks/debug/`.
- [ ] **Expected:** the second status names a different file, ending in the new session id. That file holds the new conversation's lines; the first file ends where the first conversation ended.
- [ ] **Why this matters:** before 0.4.74 the path was looked up once per process, so a new conversation's lines went on into the previous conversation's file, and diagnosing it meant reading the wrong log.

### HV.17 — A mark on a line inside a reply's table leaves the table whole (0.4.92)

- [ ] **Steps:** in a reply that has a markdown table, select a few words in one of its rows (not the header), then press the leader, `m`, and a letter.
- [ ] **Expected:** the table still draws as a table, every row in place; the marked words show in the bold `«a»` form inside their row, rather than the row being pulled out on its own line.
- [ ] **Why this matters:** before 0.4.92 the marked row was drawn alone and the rows after it lost their header, so they showed as raw `| ... |` text until the highlight cleared.

### HV.16 — Setting the reading position never moves the view, even with the prompts pane open (0.4.89)

- [ ] **Setup:** `/bm-debug on`.
- [ ] **Steps:** with some conversation on screen, press the leader, then `p`: the prompts pane opens. Start typing in the input box so the band stops waiting for a number (the pane stays open). Scroll the conversation well away from where it was, select a few words in a message now on screen, then press the leader and Space.
- [ ] **Expected:** the toast says "reading position set", the selected words are highlighted, and the view does not move. The debug log says "view kept after highlight" (or, if the redraw did move it, "view restored after highlight" naming the message you were looking at, never the one on screen when the pane opened).
- [ ] **Why this matters:** before 0.4.89 a list pane left open kept its opening position as the place to put the view back, and setting the reading position scrolled there, minutes or hours later (Q261015-01). The kit test `reading.test.ts` covers the logic; only a live session shows the scroll itself.

### HV.15 — A second pane does not inherit the first pane's Esc watcher (0.4.82)

- [ ] **Setup:** bind a key to the prompts command in `~/.claude/keybindings.json`, in the `Chat` context: `"ctrl+x p": "command:bm-prompts"`. Turn the debug log on: `/bm-debug on`.
- [ ] **Steps:** press the leader, then `m`: the mark pane opens and the band holds the keyboard (its watcher starts). Without pressing a letter or Esc, press `Ctrl+X p`: the prompts list opens in place of the mark pane. Then click into the input box.
- [ ] **Expected:** the prompts list stays open (a list stays when you go to type, by default), and the debug log's settle line names `list`, not `mark`. Before 0.4.82 the mark pane's watcher was still running and closed the list as if it were a mark pane. (Typing `/bm-prompts` instead does not show it: typing moves the keyboard to the input box first, which already ends the mark pane's watch.)
- [ ] **Why this matters:** the first pane's watcher used to keep running with the first pane's kind and settle the second as if it were a mark pane (scenario S6). The kit cannot reach the band's focus calls, so this is a hand check.

### HV.14 — Claude's permalinks stay out of the bookmarks pane (0.4.80)

Validates: the links Claude writes into its replies (permalinks) are not listed under `<leader> b`; named bookmarks, yours and Claude's, still are.

- [ ] **Steps:** in a conversation where Claude has cited earlier places with links (most replies that link back do), and where you or Claude also saved a named bookmark, press the leader, then `b`; cycle the groups with `h` and `l`.
- [ ] **Expected:** only named bookmarks appear, in every group; the counts in the header match; Claude's links in its replies still jump when clicked.
- [ ] **Why this matters:** djdarcy, 2026-10-14: "more often than not I do NOT want visible bookmark links in "Claude's" list in the "<leader>b" panel I just want permalinks that live in the message". A Permas group is #38.

### HV.13 — `/resume` brings back the resumed conversation's own state (0.4.75)

Validates: HV.10-HV.12's resets happen at `/clear` and `/resume` at all (before 0.4.75 they were tied to an event that never fires there), and a resumed conversation's marks, jumplist and bookmarks come back with it.

- [ ] **Steps:**
  1. In conversation A, set a mark (`<leader> m a`), make two jumps, and have Claude bookmark something. Note A's session id (`/bm-env`).
  2. `/clear`; in the new conversation, `/bm-debug status`, and look for the line "a new conversation: ... -> ..." in the new log.
  3. `/resume` conversation A. Scroll to the marked line; press the leader, `'`, `a`; press the leader, `o`; press the leader, `b`.
- [ ] **Expected:** after `/clear`, the new log starts with the "a new conversation" line, and HV.10-HV.12 hold. After `/resume`, A's marked line is tagged as before, `'a` jumps to it, `o` walks A's jumps, `b` lists A's bookmarks, and `p` lists A's prompts, the older ones included (0.4.79: the back-fill runs for a conversation the process moves to). Nothing from the cleared conversation shows.
- [ ] **Why this matters:** the engine never fires `session.start` at `/clear` or a resume (its types, 2.1.296); the plugin now notices a new conversation by its session id. This is the live proof the kit cannot give.
