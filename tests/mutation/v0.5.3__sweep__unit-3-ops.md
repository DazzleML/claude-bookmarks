## Triage

- **M9, equivalent.** `applyOp`'s `claim` looks the record up by identity restricted to Claude's list, then calls `claim(reg, rec.uuid)`, which itself looks on Claude's list by uuid and errors when nothing is there. Dropping the restriction changes only which error message a mis-aimed id gets; with `n` present the owner is not consulted anyway (identity ignores the owner across a claim). Recorded in `equivalents.md`.
- **M11, killable.** On a rev tie the left-hand copy (the caller's own) is the base; the contract is "the caller's copy wins the tie", now pinned by `union: on a rev tie the left-hand copy is the base...`.
- **M13, equivalent.** The first `tombAt(tomb) >= lastTouched(r)` is an early `continue`; the `kept` filter below applies the same comparison to every record, so a record the first site lets through is removed by the second. The two sites agree by design; a change to one without the other is caught by `kept`. Recorded in `equivalents.md`. (The boundary itself -- a removal stamped at the very instant of the last touch removes -- is now pinned by the same new test.)

## Caveats

A kill proves the suite noticed *this* change, not that it tests the right thing. **A clean sweep is evidence about the mutations tried, not proof of suite completeness.** The red-green audit of the unit's own 13 tests (8 anchors / 5 guards, `tests/one-offs/`'s `audit3` pattern on scratch copies) is the separate check that those tests are attached to the change.
