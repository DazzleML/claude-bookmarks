# Human Test Checklist: The debug echo is per conversation (v0.2.1)

**Target version:** 0.2.1
**Ships with commit:** v0.2.1: the debug echo is per conversation (TBD at commit)
**Ships after:** v0.2.0, `4d51e03`
**Companion automated tests:** none for this change. The 32 tests under `hooks/core/` (anchor 13, transcript-lines 9, register-file 10, `node --test`) cover the pure modules, which this change does not touch; the 9 version tests (`python -m pytest tests/test_version.py`) keep `plugin.json` and `version.py` in step. `tsc -p . --noEmit` and `claude plugin validate .` must pass; `validate` must list `CONVO_BOOKMARKS_DEBUG` under both env reads and env writes.

## What this is

v0.2.0 shipped `/bm-debug on|off` as one setting shared by every conversation on the machine, so turning the echo off in one session silenced every other. v0.2.1 makes the choice per conversation and adds a machine-wide default and a force. Everything here is about which sessions draw the plugin's dim log rows and which do not, which no automated test can see: it takes two live sessions, a hot reload, a resume and a shell. Run it on Windows first (the author's platform); the POSIX forms are given for the other two.

Vocabulary, as `/bm-debug status` prints it:

| State | Meaning |
|---|---|
| `off, the default` | No choice in this conversation; the default is off. A fresh install is here. |
| `on here only (this conversation's choice; the default is off)` | This session asked for the echo; no other session is affected. |
| `on everywhere, forced` / `off everywhere, forced` | Every conversation obeys, no exceptions, until `/bm-debug default on|off` lifts it. |

## Prerequisites

1. Claude Code 2.1.295 or later with the plugin loaded in a shell-started session (`CLAUDE_CODE_PLUGIN_DIRS` pointing at the checkout, or the installed plugin). A daemon-hosted session may not load the plugin.
2. Two folders to open sessions in; call the sessions **X** (the one you debug) and **Y** (the bystander). They can be any two conversations.
3. `/bm-env` in each: both report `convo-bookmarks 0.2.1`.
4. **State isolation.** The only persisted state this feature writes is one key, `debug:echo`, in Claude Code's plugin store, `~/.claude/plugins/store/convo-bookmarks_inline-<id>.json`. Before you start, note whether that key exists:

   **cmd.exe**:
   ```cmd
   python -c "import json,glob;[print(p,[k for k in json.load(open(p,encoding='utf-8')) if k.startswith('debug')]) for p in glob.glob(r'%USERPROFILE%\.claude\plugins\store\convo-bookmarks_inline-*.json')]"
   ```

   **PowerShell**:
   ```powershell
   python -c "import json,glob;[print(p,[k for k in json.load(open(p,encoding='utf-8')) if k.startswith('debug')]) for p in glob.glob(r'$env:USERPROFILE\.claude\plugins\store\convo-bookmarks_inline-*.json')]"
   ```

   **POSIX**:
   ```bash
   python -c "import json,glob;[print(p,[k for k in json.load(open(p,encoding='utf-8')) if k.startswith('debug')]) for p in glob.glob('$HOME/.claude/plugins/store/convo-bookmarks_inline-*.json')]"
   ```

   Read only; never edit the store file by hand while a session is open. The reset between sections is `/bm-debug default off` (clears any force) in any session, then `/bm-debug reset` in X and Y.
5. A "band action" below means `Ctrl+]` then `p`, then `Esc`: it opens and closes the prompts pane and makes the plugin log several lines.

## High-Value Verification (~5 minutes)

**If you only have 5 minutes**, run these five. They are the reason the version exists.

### HV.1 — The echo is per conversation

Validates: `/bm-debug on` in X draws rows in X and nowhere else (design check C2).

- [ ] **Steps:**
  1. In X: `/bm-debug on`, then a band action.
  2. In Y: a band action.
  3. `/bm-debug status` in both.
- [ ] **Expected:** X shows dim `convo-bookmarks` rows after its action; Y shows none. X's status says `on here only (this conversation's choice; the default is off)`; Y's says `off, the default`.
- [ ] **Why this matters:** this is the v0.2.0 defect: one session's switch reached every other.

### HV.2 — The choice survives the plugin reloading

Validates: the choice lives in the session's environment, not in module state (C1).

- [ ] **Steps:** with X on from HV.1, save any file under the plugin's `hooks/` folder (add and remove a blank line), wait two seconds, then a band action in X.
- [ ] **Expected:** X still echoes. Y still does not.
- [ ] **Why this matters:** during development the mod reloads on every save; a choice that a reload forgot would be unusable for the one person who needs it.

### HV.3 — A force reaches every session at once, with no reload

Validates: nothing is cached; a force typed in one session is obeyed by the others on their next log line (C9).

- [ ] **Steps:**
  1. In Y: `/bm-debug on`, a band action (Y echoes).
  2. In X: `/bm-debug force off`. Do not save anything.
  3. In Y: a band action, then `/bm-debug status`.
- [ ] **Expected:** Y draws nothing after step 3; its status says `off everywhere, forced (/bm-debug default off lifts it; this conversation asked for on, which applies once the force is lifted)`.
- [ ] **Why this matters:** "guarantee it is off everywhere" is the point of `force`; if it waited for a reload, the guarantee would be false.

### HV.4 — Lifting the force restores each session's own choice

Validates: a session's choice is kept under a force and applies afterwards (C10).

- [ ] **Steps:** continuing from HV.3, in X: `/bm-debug default off`; in Y: a band action, `/bm-debug status`.
- [ ] **Expected:** Y echoes again; status says `on here only`.
- [ ] **Why this matters:** a force must not erase what each session asked for.

### HV.5 — A fresh install is off and overridable

Validates: no key in the store reads as `{default: false, forced: false}` (djdarcy's requirement of 2026-10-09: "default off is the default to new shipping machines").

- [ ] **Steps:** run the store inspection from Prerequisites step 4 on a machine or profile where `/bm-debug default` and `force` have never been typed; then `/bm-debug status` in any session there.
- [ ] **Expected:** the inspection prints `[]` for `debug` keys (or only the v0.2.0 `debug:uiEcho` key, which v0.2.1 ignores); status says `off, the default`.
- [ ] **Why this matters:** the echo spamming a new user's conversations is the complaint this whole feature answers.

## Section 1: The per-conversation commands (~3 min)

### 1.1 `off` and `reset`

- [ ] **Steps:** in X: `/bm-debug on`, band action; `/bm-debug off`, band action; `/bm-debug reset`, `/bm-debug status`.
- [ ] **Expected:** rows after the first action, none after the second; status ends at `off, the default`. Each command answers with a toast and a dim line (the answer is drawn whatever the echo setting).

### 1.2 `off` is an explicit choice, not "no choice"

- [ ] **Steps:** in X: `/bm-debug default on`; in Y: `/bm-debug off`, band action, `/bm-debug status`; then in Y: `/bm-debug reset`, band action.
- [ ] **Expected:** Y is silent after `off` and its status says `off here only (this conversation's choice; the default is on)`; after `reset` Y echoes, following the default. Finish with `/bm-debug default off` in X.

### 1.3 A resumed conversation forgets

- [ ] **Steps:** in X: `/bm-debug on`; note X's session id from `/bm-env`; quit X (`/exit` or `Ctrl+C` twice); start it again with `claude --resume <id>` from the same folder; `/bm-debug status`.
- [ ] **Expected:** `off, the default`. `/bm-debug on` restores it. (Design check C5: forgetting is the chosen behaviour, not a defect.)

## Section 2: The same signal from the shell (~3 min)

### 2.1 Start a session with the echo on

- [ ] **Steps** (pick your shell), from a third folder:

  **cmd.exe**:
  ```cmd
  set CONVO_BOOKMARKS_DEBUG=1
  claude
  ```

  **PowerShell**:
  ```powershell
  $env:CONVO_BOOKMARKS_DEBUG = "1"
  claude
  ```

  **POSIX**:
  ```bash
  CONVO_BOOKMARKS_DEBUG=1 claude
  ```

  Then `/bm-debug status`, a band action.
- [ ] **Expected:** `on here only (this conversation's choice; the default is off)`; rows are drawn. X and Y are unaffected.
- [ ] **Check:** `/bm-debug off` in this session silences it (the command overrides the variable it was started with, since both are the same variable).

### 2.2 An explicit off from the shell

- [ ] **Steps:** as 2.1 with the value `0` (also try `off` and `false`), after `/bm-debug default on` in X.
- [ ] **Expected:** the new session is silent and says `off here only`. Finish with `/bm-debug default off` in X. Unset the variable afterwards: cmd.exe `set CONVO_BOOKMARKS_DEBUG=`; PowerShell `Remove-Item Env:\CONVO_BOOKMARKS_DEBUG`; POSIX `unset CONVO_BOOKMARKS_DEBUG` (the one-line POSIX form in 2.1 sets it for that command only).

### 2.3 A child process inherits the choice

- [ ] **Steps:** in X (echo on by `/bm-debug on`), start a fork or a subagent from the conversation (ask Claude to "fork a quick agent that runs `/bm-env`", or use the Agent tool with a trivial task); read the child's log file under `<CLAUDE_USER_DIR>/bookmarks/debug/`.
- [ ] **Expected:** the child's log has its own session id file; whether a child *draws* rows is not observable from X. This step only confirms nothing breaks; mark it MANUAL/informational.

## Section 3: `/bm-env` and the status line (~2 min)

### 3.1 `/bm-env` prints with the echo off

- [ ] **Steps:** in Y with status `off, the default`: `/bm-env`.
- [ ] **Expected:** two dim `[bm-poc]` lines appear (version, session id, captured counts; then the dcc-patcher line ending in `log echo off, the default`). In v0.2.0 these lines were subject to the echo and printed nothing when it was off.

### 3.2 Status wording in every state

- [ ] **Steps:** cycle through: `/bm-debug status` (default), `/bm-debug on` + status, `/bm-debug force on` + status, `/bm-debug default on` + status (in a session with no choice), `/bm-debug default off`.
- [ ] **Expected:** the sentences in the vocabulary table above, each followed by `; file log: <path>; /bm-debug on|off|reset ...`. No sentence says "on" when rows are not drawn, or the reverse.

### 3.3 Unknown argument

- [ ] **Steps:** `/bm-debug maybe`, `/bm-debug default`, `/bm-debug force maybe`.
- [ ] **Expected:** each prints the status line with the usage; nothing changes.

## Section 4: Store hygiene and docs (~2 min)

### 4.1 Exactly one key

- [ ] **Steps:** after all of the above, run the store inspection from Prerequisites step 4.
- [ ] **Expected:** the `debug` keys are `debug:echo` and, on a machine that ran v0.2.0, the orphaned `debug:uiEcho`; nothing per conversation (design check C7). The value of `debug:echo` is `{"default": false, "forced": false}` after the reset.

### 4.2 Docs agree with the behaviour

- [ ] **Steps:** read `docs/usage.md` "The log echo" and `docs/troubleshooting.md` "The debug log" against what you saw.
- [ ] **Expected:** every command in the table exists and does what the row says; the README command table has the `/bm-debug` row; the CHANGELOG `[0.2.1]` entry describes the per-conversation behaviour, and `[0.2.0]` still describes the shared switch it shipped with.

### 4.3 A pane in a narrow terminal (docs only)

- [ ] **Steps:** shrink the terminal under about 110 columns and press `Ctrl+] p`.
- [ ] **Expected:** no pane; a toast says Claude Code refused to draw it and why. `docs/troubleshooting.md` "A pane doesn't open in a narrow terminal" describes this and the remedy (widen, or a smaller font).

## What the automated tests DON'T cover

- Which sessions draw dim rows: needs two live Claude Code processes.
- Whether `$.env.set` is visible to the same process's `$.env.get` and survives a hot reload (HV.2).
- Propagation of a store write to another process's next read (HV.3).
- Resume forgetting the choice (1.3), shell variable forms (Section 2), the status wording (3.2), `/bm-env` drawing with the echo off (3.1).
- Terminal width and the pane refusal (4.3).

## Reporting issues found

1. Note the section and step number.
2. In the affected session, `/bm-debug status` and `/bm-env`; copy both lines.
3. Attach the last lines of `<CLAUDE_USER_DIR>/bookmarks/debug/<session id>.log` for X and Y.
4. File an issue on DazzleML/claude-bookmarks referencing this checklist and v0.2.1.

## Cleanup

- `/bm-debug default off` in any session (clears a force and the default).
- `/bm-debug reset` in X and Y.
- Unset `CONVO_BOOKMARKS_DEBUG` in any shell where Section 2 set it (forms in 2.2).
- The store keeps `debug:echo` as `{"default": false, "forced": false}`; that is the shipped default and needs no removal. The orphaned v0.2.0 key `debug:uiEcho` may be left; it is read by nothing.
