## Triage

Every survivor was **killable**; none equivalent, none don't-care. The killing tests, written before this report:

- `tests/core/register-file.test.ts` -- "parse normalises what it keeps" (M4, M5, M6); the `reading: null` key in `newerBuildFile` (N6).
- `plugin/tests/guard.test.ts` -- the newer-build toast counted once at load and twice after the refused save (M9); the writer stamp and `list` after the relabel (N8, N9); the "loaded its .bak" line present for a torn file and absent for a good one (N10).

Two things the sweep said about the suite as it was: the kit never checked what a save wrote back as `writer`, or that the cache followed the save; both were pre-existing gaps inside this unit's functions, now closed.

## Anomalies

- N5's `original` arrived from the generator with the newline literal escaped once too few for the JSON; applied 0 times. Re-spelt by hand (`chr(92)` + `n`), applied once, killed. Recorded so the next sweep spells it right in the spec.
- No restore mismatches: the harness never mutates the live tree (fresh copies), and `git status --short` was identical before and after each run.

## Caveats

A kill proves the suite noticed *this* change, not that it tests the right thing. **A clean sweep is evidence about the mutations tried, not proof of suite completeness.** The red-green audit of the unit's own six tests (5 anchors / 1 guard) is the separate check that those tests are attached to the fix.
