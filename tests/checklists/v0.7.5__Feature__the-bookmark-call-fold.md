**Target version:** 0.7.5
**Ships with commit:** TBD (`feat(bookmarks): fold Claude's bookmark calls into one line per reply (v0.7.5)`)
**Companion automated tests:** `tests/core/tool-fold.test.ts` (6: grouping by turn, the two levels, which results show, finding the answer, the call's line, the fold's line), `plugin/tests/tool-fold.test.ts` (3: a call's row draws its line and its result nothing until opened; ctrl+o is Claude Code's own drawing; another tool is untouched). Red-green: 6 deliberate breaks of the fold, all caught.

## What this is

A short hand check of how Claude's calls to the plugin's `bookmark` tool now draw: one fold per reply instead of a row and a block of JSON per call. The kit shows what a row returns, not how the TUI lays it out, whether a press reaches it, or how ctrl+o treats it, so those are checked here, live.

## Prerequisites

Claude Code with the plugin at 0.7.5 (`/bm-env` shows it). The fold writes no files and changes no settings, so no isolation is needed; the links minted below land on Claude's own list, as any `/bmlinks` turn's do.

## High-Value Verification (~5 minutes)

### HV.1: a reply's calls fold to one line

- [ ] **Steps:** ask Claude for a `/bmlinks` recap with three or more links.
- [ ] **Expected:** where the first `bookmark` call was, one dim line `⚓ 3 bookmark calls ▸` (the count matching the calls); no `bookmarks - bookmark (MCP)(…)` rows and no JSON between the prompt and the reply. The reply's links work as before.
- [ ] **Why this matters:** this is the change; without it every link costs a screen of JSON.

### HV.2: two levels open in place

- [ ] **Steps:** press the `⚓ … ▸` line; then press one call's line; then press both again.
- [ ] **Expected:** the fold reads `▾` and lists one line per call, `⚓ bookmark #95: <label> ▸` (an ambiguous call says how many places hold the fragment). Pressing a call's line shows that call's row and answer as Claude Code draws them, under it. Pressing again closes each.
- [ ] **Why this matters:** nothing is lost, only tucked away.

### HV.3: ctrl+o shows everything

- [ ] **Steps:** with the fold closed, press ctrl+o; press it again to leave.
- [ ] **Expected:** in the transcript view every bookmark call and its answer draw in full.

### HV.4: other tools are untouched

- [ ] **Expected:** Bash, Read and every other tool's rows in the same reply draw as they always have.

### HV.5: calls from before a reload

- [ ] **Steps:** restart Claude Code (or resume the conversation), scroll to the `/bmlinks` reply from HV.1.
- [ ] **Expected:** each of its calls draws its own `⚓ bookmark #n: <label> ▸` line (they belong to no reply this load saw), each opening on its own. No JSON unless opened.

## What the automated tests DON'T cover

- How the TUI lays the fold out: blank lines left by hidden rows, the dim style, narrow panes.
- The count redrawing as a reply's later calls arrive (the first row should go from 1 to 3).
- Whether a press on the line reaches it in every terminal.

## Reporting issues found

Note the HV number, copy what the reply drew (a paste is enough), and file an issue against v0.7.5.
