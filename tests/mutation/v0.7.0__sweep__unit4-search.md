## Triage

- **M9 was the find with a user-visible cost.** A JavaScript regex with `g` (or `y`) keeps its `lastIndex` between `test()` calls, so `m/loader/g` would miss every other matching row. Stripping the two flags is what makes them harmless, and now a test holds it.
- **M7, equivalent.** A token is a run of non-whitespace, so it never holds a newline; the `s` flag on the reader of `m/...` changes nothing.
- **M8, don't-care.** `m//` is an empty pattern and matches every text, which is what a regex engine does with it; nobody types it to mean anything else. Read as a word instead, it would match the literal text `m//`. Neither is wrong enough to pin.
- **M12, equivalent.** The place reader writes rows in piece order (a row's piece never decreases along the index, and a resume keeps appending to the open piece), so flattening the rows in scope piece by piece is already sorted.

## Caveat

A kill proves the suite noticed *this* change, not that it tests the right thing, and **a clean sweep is evidence about the mutations tried, not proof of suite completeness.**
