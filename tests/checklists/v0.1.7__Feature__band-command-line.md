# Human Test Checklist: The band as the command line

**Target version:** 0.1.7
**Ships with commit:** v0.1.7: the band is the command line (TBD at commit)
**Companion automated tests:** none for these features. The 9 tests in `tests/test_version.py` cover repo tooling only (version and manifest); the plugin's own tests arrive with the core rebuild (#5). Everything below is checked by hand. Items marked **[verified 2026-10-07]** were run live by the maintainer on Claude Code 2.1.290, Windows Terminal, during development.

## What this is

A hand-run check of the v0.1.7 keyboard model. The leader is Claude Code's own `abovePrompt:focus`, which moves the keyboard to the plugin's band. The band's field takes the first key, and band buttons take the rest. Everything here depends on keyboard focus and on which Claude Code calls count as "person-initiated", which no automated test here can drive. Run it before tagging, and after any Claude Code update that touches the band, panes or keybindings.

## Prerequisites

1. **Claude Code 2.1.290** (or note your version), fullscreen renderer (`/tui fullscreen`).
2. **The plugin loaded** at v0.1.7: `/bm-env` reports `convo-bookmarks 0.1.7`.
3. **The leader bound.** Back up `~/.claude/keybindings.json`, then add `"ctrl+]": "abovePrompt:focus"` to its `Chat` block. To test without it, use `Ctrl+X Tab` wherever this says `Ctrl+]`.
4. **A conversation with a few screens of history**, and at least one mark set (`Ctrl+] m a` after scrolling somewhere).
5. **The debug log**, for the log checks. `/bm-env` shows the session id; the log is `<user dir>/bookmarks/debug/<session id>.log`, where the user dir is `CLAUDE_USER_DIR` if set, otherwise `~/claude`. To see its last lines:

   **cmd.exe**:
   ```cmd
   powershell -NoProfile -Command "Get-Content \"$env:USERPROFILE\claude\bookmarks\debug\<session id>.log\" -Tail 15"
   ```

   **PowerShell**:
   ```powershell
   Get-Content "$env:USERPROFILE\claude\bookmarks\debug\<session id>.log" -Tail 15
   ```

   **POSIX**:
   ```bash
   tail -n 15 ~/claude/bookmarks/debug/<session id>.log
   ```

**Reset between sections:** press `Esc` until the keyboard is back in the input box, and delete test marks with `/bm-delmarks <letters>`.

**A draft**, where a step says "with a draft": type a few words in the input box and don't send them. After the step, the words must still be there, unchanged.

## High-Value Verification (~5 minutes)

### HV.1: A jump over a draft [verified 2026-10-07]

Validates: the leader works with text in the input box, and the jump is a band press.

- [ ] **Steps:** with a draft, press `Ctrl+]`, then `'`, then the letter of a set mark.
- [ ] **Expected:** the view jumps to the mark; the draft is untouched. The **very first** jump on a new Claude Code version instead ends with the toast "Press Enter to jump to …": press `Enter` once, and later jumps go straight through.
- [ ] **Why this matters:** jumping while you're mid-prompt is the reason for the band leader; every other route failed this.

### HV.2: Mark the top of the screen [verified 2026-10-07]

- [ ] **Steps:** with nothing selected, scroll somewhere, press `Ctrl+] m b`. Scroll far away, then `Ctrl+] ' b`.
- [ ] **Expected:** the mark toast says `[top of screen]`; after the mark, the view is back where it was before the pane opened; the jump lands on that message.
- [ ] **Why this matters:** marking "where I am" without selecting anything is the common case.

### HV.3: The reading position, there and back [verified 2026-10-07]

- [ ] **Steps:** set a reading position (select a line, `Ctrl+] Space Space`). Scroll to the bottom. Press `Ctrl+] Space Space`, then `Ctrl+] Space Space` again.
- [ ] **Expected:** the first goes to the reading position; the second returns to the same text you were reading at the bottom.
- [ ] **Why this matters:** the most-used key; "back" must land where you were.

### HV.4: Browse the prompts [verified 2026-10-07]

- [ ] **Steps:** `Ctrl+] p`, then Down three times, Up once, then `Enter`.
- [ ] **Expected:** a `▶` moves through the pane's list as you press, the pane's `#` field shows the number, and `Enter` jumps to that prompt.
- [ ] **Why this matters:** finding "the prompt that's yours" by eye is what the pane is for.

### HV.5: Getting back to typing

- [ ] **Steps:** after any command above, type a letter, then press `Esc` and type a letter.
- [ ] **Expected:** before `Esc`, the letter goes to the band (the `bm:` field, or a hint toast); after `Esc`, it goes into the input box.
- [ ] **Why this matters:** the one thing people must learn; if `Esc` fails, the plugin traps the keyboard.

## Section 1: Setup and the field

### 1.1 The band at rest

- [ ] **Expected:** above the input box, `bm:` followed by a field (`' j m p ␣`) and the buttons `m: mark  j: jump  p: prompts  r: read`.

### 1.2 The leader puts the keyboard in the field [verified 2026-10-07]

- [ ] **Steps:** press `Ctrl+]`.
- [ ] **Expected:** the field takes the keyboard; the log shows `[diag] focus AbovePrompt -> band-cmd-N by person`.

### 1.3 `Ctrl+X Tab` works without a binding

- [ ] **Steps:** remove the `ctrl+]` line (keep the backup), restart, press `Ctrl+X Tab`, then `'` and a letter.
- [ ] **Expected:** the same as HV.1.

### 1.4 An unknown key [verified 2026-10-07]

- [ ] **Steps:** `Ctrl+]`, then `x`.
- [ ] **Expected:** a toast listing the keys; no mark, no jump, no `x` in the input box.

### 1.5 A second leader press keeps the focus on the field [verified 2026-10-07]

- [ ] **Steps:** `Ctrl+] Space Space`, then immediately `Ctrl+] Space Space` again.
- [ ] **Expected:** there and back; the mark pane never opens. The log may show `band focus kept on the command field`.

## Section 2: Marks

### 2.1 A fresh selection is used [verified 2026-10-07]

- [ ] **Steps:** select a few words, then within a minute `Ctrl+] m c`.
- [ ] **Expected:** toast `[selection]`; the log shows `selection "…" is Ns old: used`.

### 2.2 A stale selection is ignored [verified 2026-10-07]

- [ ] **Steps:** select a few words, wait over 75 seconds, then `Ctrl+] m d`.
- [ ] **Expected:** toast `[top of screen]`; the log shows `… is Ns old: ignored (stale)`.

### 2.3 `Enter` cancels [verified 2026-10-07]

- [ ] **Steps:** `Ctrl+] m`, then `Enter`.
- [ ] **Expected:** no mark set; the pane closes; the view returns to where it was.

### 2.4 Delete marks

- [ ] **Steps:** `/bm-delmarks c d`, then `/bm-marks`; then `/bm-delmarks zz` (no such letters).
- [ ] **Expected:** a toast `deleted marks c d`, and `/bm-marks` no longer lists them; then `not set: …` or the usage hint.

## Section 3: Jumps and the reading position

### 3.1 `j` and `'` are the same [verified 2026-10-07]

- [ ] **Steps:** `Ctrl+] j a`, then scroll away, then `Ctrl+] ' a`.
- [ ] **Expected:** both jump to `a`.

### 3.2 `Enter` in the jump pane goes to the reading position

- [ ] **Steps:** `Ctrl+] '`, then `Enter`.
- [ ] **Expected:** the reading position (or back, if you're already there).

### 3.3 `r` and `Space Enter` [verified 2026-10-07]

- [ ] **Steps:** `Ctrl+] r Enter`; `Ctrl+] Space Enter`.
- [ ] **Expected:** each behaves like `Ctrl+] Space Space`.

### 3.4 "Stays put" only when it should [verified 2026-10-07]

- [ ] **Steps:** scroll to the reading position by hand, then `Ctrl+] Space Space`.
- [ ] **Expected:** the toast "You're at the reading position"; the view doesn't move. From the bottom (HV.3) it must **not** say this.

## Section 4: The prompts pane from the band

### 4.1 A number waits for `Enter` [verified 2026-10-07]

- [ ] **Steps:** `Ctrl+] p`, type a three-digit number slowly, then `Enter`.
- [ ] **Expected:** the `#` field fills digit by digit, the `▶` and the list follow, nothing jumps until `Enter`.

### 4.2 `j`/`k`

- [ ] **Steps:** `Ctrl+] p`, `j` `j` `k`, `Enter`.
- [ ] **Expected:** the same as HV.4.

### 4.3 Pin from the band

- [ ] **Steps:** `Ctrl+] p`, `k` twice, `s`; then `s` again.
- [ ] **Expected:** a toast `pinned #N`, and that row reads `N★)`; the second `s` unpins it. The band stays in prompt mode throughout.

### 4.4 Left/Right (untested)

- [ ] **Steps:** `Ctrl+] p`, then Right, then Left.
- [ ] **Expected:** Right acts like Down, Left like Up. Record what actually happens.

### 4.5 A click into the pane hands it the keyboard [verified 2026-10-07]

- [ ] **Steps:** `Ctrl+] p`, click in the pane's `#` field, type a number, `Enter`.
- [ ] **Expected:** the pane stays open; the jump happens; the log shows `the keyboard moved into the pane`.

## Section 5: Clicks and typed commands

### 5.1 Clicking a band button over a draft [verified 2026-10-07]

- [ ] **Steps:** with a draft, click `prompts` on the band.
- [ ] **Expected:** the pane opens and stays open as a list; click a prompt to jump, or close it with its `×`.

### 5.2 Lost clicks (open issue)

- [ ] **Steps:** click band buttons several times in different situations (after `Esc`, after the arrows, while Claude works).
- [ ] **Expected:** each click opens its pane. If one does nothing, note what you did just before, and copy the log's last lines.

### 5.3 Typed commands from an empty input box

- [ ] **Steps:** with an empty input box, type `/bm-prompts` and `Enter`, then use the arrows and `Tab` in the pane.
- [ ] **Expected:** the pane holds the keyboard; arrows and `Tab` move in it.

### 5.4 Typed commands over a draft

- [ ] **Steps:** type a draft, then (by pasting or a `command:` keybinding) run `/bm-goto`.
- [ ] **Expected:** a toast pointing to the band leader; the draft is untouched.

## Section 6: Optional fast keys

### 6.1 `Ctrl+X Space` [verified 2026-10-07]

- [ ] **Steps:** add `"ctrl+x space": "app:diffFileListDown"` to the `Chat` block, then with a draft press `Ctrl+X Space` twice.
- [ ] **Expected:** there and back, in one step each, with the draft untouched.

### 6.2 A leader can't also start a chord [verified 2026-10-07]

- [ ] **Steps:** add `"ctrl+] space": "app:diffFileListDown"` beside `"ctrl+]": "abovePrompt:focus"`, then press `Ctrl+] '` and a letter. Remove the line afterwards.
- [ ] **Expected:** `Ctrl+]` alone stops working (a Claude Code limit, documented).

## Section 7: While Claude works, and diagnostics

### 7.1 While Claude works [verified 2026-10-07]

- [ ] **Steps:** send a prompt that takes a while, and during the reply run HV.1 and HV.2.
- [ ] **Expected:** the same as when idle; the log's `[diag]` lines show `claude BUSY`.

### 7.2 `/bm-diag-keys`

- [ ] **Steps:** `/bm-diag-keys on`, type a few letters, `/bm-diag-keys off`.
- [ ] **Expected:** the log gets one `[diag] edit …` line per key, with lengths and key names only, never the text; then none.

## What the automated tests DON'T cover

- Keyboard focus between the input box, the band and panes (all of the above)
- Which calls Claude Code counts as person-initiated (jumps from the band, the one-time check)
- The view shifting when a pane opens or closes, and the return
- Toast wording and timing
- Other terminals (macOS Terminal, iTerm2, Linux terminals, tmux), other leader keys, and Claude Code versions after 2.1.290 (2.1.292 is untested)
- Dialogs: what the leader does while a permission prompt is up (untested)

## Reporting issues found

1. Note the section and step.
2. Copy the last 15 lines of the debug log (see Prerequisites).
3. Note the Claude Code version (`claude --version`), the terminal, and whether the input box held a draft.
4. File an issue on DazzleML/claude-bookmarks referencing this checklist and v0.1.7.

## Cleanup

- Delete test marks: `/bm-delmarks <letters>` (or `all`).
- Unpin test pins: `Ctrl+] p`, move to the prompt, `s`; or `/bm-pin N`.
- Restore `~/.claude/keybindings.json` from your backup if you changed it for Sections 1.3 or 6.

Nothing outside Claude Code's plugin storage and your keybindings file is changed.
