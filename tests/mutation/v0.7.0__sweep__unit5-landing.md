## Triage

- **M3 and M4, equivalent.** Neither call site ever starts on a message. `messageBefore` is called with a target that is not a message (a message returns earlier), or with the Agent call's row, which is a tool call. So starting one row earlier finds the same message.
- **M6, equivalent.** The only main row besides the call that carries the Agent call's id is the call's own result, and a result always follows its call in the file, so `findIndex` finds the call first.
- **M8, equivalent.** A stored-output place never carries `stored` (only the tool result that refers to the file does), so it can never match itself.

## Also from this unit's red-green audit

The audit's L8 mutant, which dropped "only a record's first block is a message", *passed* the tests. The mutant was right and the code was wrong. A reply that is the second block of its record (thinking, then text) is still a message, and Claude Code scrolls to the record's uuid, which the blocks share. The condition is gone, and a test pins the reply landing on itself: an **anchor**, the unit's only one.
