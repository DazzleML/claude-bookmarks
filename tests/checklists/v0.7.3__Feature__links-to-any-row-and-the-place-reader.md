# Human Test Checklist: links to any row, and the place reader on demand

**Target version:** 0.7.3
**Ships with commit:** TBD (`feat(bookmarks): links to any row the chat draws (v0.7.3)`)
**Companion automated tests:** `tests/core/record-places.test.ts` (7, records keyed by place), `tests/core/places-reader.test.ts` (+2, the catch-up and `hasPlacesIndex`), `tests/core/places.test.ts` (tool-row heads), `tests/core/diagnostics.test.ts` (`/bm-jump` with raw ids). Red-green audit: 9 mutants of the record code, every one turned a test red.

## What this is

This short checklist is the hand-run check of what 0.7.3 adds. Claude's `bookmark` tool can now link to any row the chat window draws, not only prompts and replies: tool calls, tool output and agents' messages. Behind that is the place reader, which reads all of a conversation's files the first time it is needed. The mocks cannot check where a click actually lands in the TUI, whether a folded tool group opens, or how long the first read takes on a real long conversation. A person checks those here, in a live Claude Code session.

**Not in this version:** the search pane (`<leader> /`, `/bm-search`). Both still do nothing; they arrive in 0.7.4.

## Prerequisites

1. Claude Code with the plugin at 0.7.3 loaded (`/bm-env` shows the version).
2. A conversation with at least one tool call (any `Bash` or `Read` row) and, for HV.2, one agent call (ask Claude to "use an Explore agent to list the files in this folder").
3. **Isolation (optional):** to keep the run out of your real bookmark folder, start Claude Code with `CLAUDE_USER_DIR` pointed at a scratch folder:

   **cmd.exe**:
   ```cmd
   set CLAUDE_USER_DIR=%TEMP%\bm-check
   claude
   ```

   **PowerShell**:
   ```powershell
   $env:CLAUDE_USER_DIR = "$env:TEMP\bm-check"
   claude
   ```

   **POSIX**:
   ```bash
   export CLAUDE_USER_DIR=/tmp/bm-check
   claude
   ```

   Below, `<data>` means `%TEMP%\bm-check\bookmarks` (or `~/claude/bookmarks` without isolation).

## High-Value Verification (~5 minutes)

### HV.1: a link to a tool call lands on the tool row

Validates: a place-keyed record (`file`/`part`/`drawn`) and the jump to the `tool_use` id.

- [ ] **Steps:**
  1. Ask Claude: "Bookmark the shell command you just ran, and link it in your reply."
  2. Click the link in the reply.
- [ ] **Expected:** the view scrolls to that tool row. A folded group ("Ran 1 shell command") is reached too, either folded or unfolded. No words are highlighted (a tool row has no message text to mark).
- [ ] **Why this matters:** this is the feature. A link that lands on the nearest message instead is the 0.7.2 behaviour.

### HV.2: a tool's output and an agent's message

Validates: rows outside the main transcript (stored outputs, `subagents/`).

- [ ] **Steps:**
  1. Ask Claude to bookmark a phrase from a tool's *output* and link it.
  2. Ask Claude to bookmark a phrase from the agent's reply (HV prerequisite 2) and link it.
  3. Click each link.
- [ ] **Expected:** each link mints (no `no match`). A click lands on the row Claude Code draws for that output or that agent call.
- [ ] **Why this matters:** these rows live in files the plugin did not read before 0.7.3.

### HV.3: prompts and replies are unchanged

Validates: messages keep uuid-only addressing.

- [ ] **Steps:** ask Claude to link one of your earlier prompts and one of its own earlier replies by a phrase; click both.
- [ ] **Expected:** each lands on the message with the phrase highlighted, as in 0.7.2.
- [ ] **Why this matters:** the record change touches every link; this is the regression check.

### HV.4: the first read, and "still being read"

Validates: the reader starts on demand and the tool call stays inside its time budget.

- [ ] **Steps:**
  1. In a long conversation (tens of MB), make the first link to a tool row (HV.1).
  2. If Claude reports the conversation is still being read, type `/bm-env`.
  3. Wait a minute or two and ask again.
- [ ] **Expected:** the tool answers within about 6 seconds, never with "no tool.call hook answered". `/bm-env` shows a `places:` line with progress, then "done" with an elapsed time. The retry mints the link. **Note the elapsed time** in your report: it is the first real figure for a read through Claude Code.
- [ ] **Why this matters:** a hook that waits too long is dropped by Claude Code with no answer at all.

### HV.5: the `places/` folder appears only when needed, and the note names

- [ ] **Steps** (list the folder):

  **cmd.exe**:
  ```cmd
  dir "%CLAUDE_USER_DIR%\bookmarks\places" /s /b
  dir "%CLAUDE_USER_DIR%\bookmarks\sessions" /s /b | findstr ".p0.md"
  ```

  **PowerShell**:
  ```powershell
  Get-ChildItem "$env:CLAUDE_USER_DIR\bookmarks\places" -Recurse | Select-Object FullName
  Get-ChildItem "$env:CLAUDE_USER_DIR\bookmarks\sessions" -Recurse -Filter "*.p*.md"
  ```

  **POSIX**:
  ```bash
  ls -R "$CLAUDE_USER_DIR/bookmarks/places"
  find "$CLAUDE_USER_DIR/bookmarks/sessions" -name '*.p*.md'
  ```
- [ ] **Expected:**
  - in a fresh conversation, before any tool-row link, `places/` has no folder for it;
  - after HV.1, `places/<session id>/` holds `index.json`, `index.0.jsonl` (and more) and `text.0.jsonl` (and more);
  - the tool-row bookmark's note is `<first 8 of uuid>.p<part>.md` (for example `45039059.p0.md`), while a prompt's or reply's note keeps `<first 8>.md`.
- [ ] **Why this matters:** the folder is disclosed as written only on demand; it is about the size of the conversation's text.

## Section 1: probes

### 1.1 `/bm-jump` takes raw ids

- [ ] **Steps:** `/bm-jump toolu_<id of a tool call>` (Claude can tell you one), then `/bm-jump collapsed-<uuid>` for a folded group's id if the debug log shows one.
- [ ] **Expected:** each scrolls to that row; neither is refused as "not an id".

### 1.2 Resume at the next start

- [ ] **Steps:** after HV.4 finished, quit Claude Code and resume the same conversation (`claude --resume`); type `/bm-env`.
- [ ] **Expected:** the `places:` line shows the pass resumed from the saved index (quickly done), not "not started". A conversation with no `places/` folder still shows "not started".

## What the automated tests DON'T cover

- Where a `$.ui.scroll` to a `tool_use` id lands in the real TUI, folded or unfolded.
- The real duration of the first read through Claude Code's program calls (PowerShell on Windows, `sh` elsewhere).
- Claude Code's own time limit on the tool call under a real slow read.
- Whether the link text and the "still being read" message read well.

## Reporting issues found

1. Note the HV or section number.
2. Copy the link Claude made, the reply around it, and the `/bm-env` output.
3. File an issue referencing this checklist and v0.7.3.

## Cleanup

With isolation, remove the scratch folder (`dz safedel "%TEMP%\bm-check"`, or delete it by hand) and clear the variable:

- **cmd.exe:** `set CLAUDE_USER_DIR=`
- **PowerShell:** `Remove-Item Env:\CLAUDE_USER_DIR`
- **POSIX:** `unset CLAUDE_USER_DIR`

Without isolation, the bookmarks you made are real ones; ask Claude to remove the ones you do not want (its `bookmark` tool's `remove` action). The `places/<session id>/` folder may be deleted; it is rebuilt when next needed.
