## Prerequisites

Claude Code started from a shell with the plugin loaded from this working tree, in a long conversation that has a few slash commands, a `!` shell command and an interruption in it (or make some: `/bm-pin`, `!echo hi`, `Esc` while Claude is answering).

## High-Value Verification (~5 minutes)

### HV.1 — Footnotes on a real transcript

- [ ] **Steps:** `Ctrl+] p`; find a prompt you followed with a slash command.
- [ ] **Expected:** a dim `… N footnotes` row under it; clicking it lists `N.1 /command args`, `N.2 !shell`, `N.3 Request interrupted by user`. Prompt numbers are the same as before 0.4.21. No compaction or task notification appears as a footnote.
- [ ] **Why this matters:** the back-fill reads the transcript once per conversation (`backfilled6`); a wrong rule here puts noise in the list for good.

### HV.2 — The band's `.` button

- [ ] **Steps:** `Ctrl+] p`, type the digits of a prompt with footnotes, click the band's `.`, type `1`, `Enter`.
- [ ] **Expected:** the view jumps to that footnote's message. With a `k` that does not exist, a toast says `no footnote N.k`.

### HV.3 — `/words` in the pane

- [ ] **Steps:** with an empty input box, `/bm-prompts`; type `/` and two words from an old prompt, in reverse order and in capitals.
- [ ] **Expected:** only matching prompts are listed, with their own numbers; a line above the list reads `/your words: N of M match`; pinned prompts that don't match leave the ★ group. Words found only past a prompt's visible excerpt still match.

### HV.4 — `Esc` clears first

- [ ] **Steps:** with a filter typed (HV.3), press `Esc`; then `Esc` again.
- [ ] **Expected:** the first `Esc` leaves the pane open with the whole list and an empty filter (a toast or hint saying the filter was cleared); the second closes the pane.
- [ ] **Why this matters:** the kit cannot raise the pane's close, so this path has no automated test.

### HV.5 — The settings

- [ ] **Steps:** `/config`, set "Footnotes in the prompts list" to `shown`, then `hidden`; set "Prompt text kept for the filter" to `100`, reopen the pane and filter on a word deep in an old prompt.
- [ ] **Expected:** `shown` lists every footnote unfolded, `hidden` lists none; with a 100-byte budget the deep word no longer matches old prompts (their excerpts still do), at once, without sending another prompt, and `~/claude/bookmarks/prompttext/<session>.0.json` shrinks to match. `/bm-config` shows both values with source `/config`. Set both back afterwards.

### HV.5b — The plugin store stays small

- [ ] **Steps:** after a 0.4.23 load, look (read only) at the size of the plugin's store file under Claude Code's `plugins/store/` folder.
- [ ] **Expected:** no `prompttext:` keys in it, and its size near what it was before the filter (it was 620 KB with 216 KB of them on 2026-10-12). No `backfilled`..`backfilled5` keys remain; a `seen` key lists the conversations with today's time; marks and pins of every conversation are still there. The debug log (`/bm-debug on` first) has a `[bm] store: pruned N keys (...)` line on the first start.

### HV.6 — A new conversation keeps its own text

- [ ] **Steps:** in a conversation with a filter that matches deep text, `/clear` (or `/resume` another long conversation); send one prompt; `/bm-prompts` and filter on a word deep in one of *this* conversation's older prompts.
- [ ] **Expected:** it matches. Then `/resume` back to the first conversation: its deep-text matches still work.
- [ ] **Why this matters:** the text cache lives as long as the plugin, across conversations; before 0.4.23's fix a save after a switch could overwrite the new conversation's kept text. The kit runs each test in one conversation, so this has no automated test.

## What the automated tests DON'T cover

- `Esc` clearing the filter before closing (the kit has no way to raise a pane's close)
- A conversation switch with the plugin still loaded (the kit's conversation is fixed per test)
- The pruning as wired at start-up (`session.start` does not run in a kit test)
- Real transcripts' footnote shapes beyond the measured sample
- How the dim footnote role reads on a light and a dark theme
- Store size and speed with thousands of prompts and an unlimited budget
