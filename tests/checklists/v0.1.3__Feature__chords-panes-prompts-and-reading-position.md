# Human Test Checklist: chords, panes, prompt history and reading position

**Target version:** 0.1.3
**Ships with commit:** v0.1.3 (TBD at writing)
**Companion automated tests:** 9 tests in `tests/test_version.py` (version and manifest only). The mod itself (`hooks/register.tsx`) has no automated tests yet; a test harness arrives with the core rebuild (#5). Until then this checklist **is** the verification of the mod's behaviour.

## What this is

A hand-run check of what 0.1.3 adds to the `convo-bookmarks` mod: a highlight that finds formatted lines and keeps paragraph spacing, reworked mark and jump panes, a numbered history of your prompts (`Ctrl+X p`) back-filled to the conversation's first message, and a reading position you set and swap to with one chord (`Ctrl+X Space`). Everything here happens in a live Claude Code terminal, which no mock can stand in for: keys, selections, scrolling and drawing.

## Prerequisites

1. **Claude Code 2.1.288 or 2.1.289**, fullscreen renderer (`/tui fullscreen`), dark theme. On another build the mod toasts a warning at start-up; the chords may still work.
2. **Load the mod from your working copy**, in a session started from a shell (not one hosted by the background daemon, for example the original of a `/fork`): either `claude --plugin-dir <path to this repo>`, or `CLAUDE_CODE_PLUGIN_DIRS` set to that path in the `env` block of `~/.claude/settings.json`.
3. **Keybindings.** Back up `~/.claude/keybindings.json`, then make sure its `Global` block holds:

   ```json
   "ctrl+x m": "app:toggleDiffNoiseFilter",
   "ctrl+x '": "app:toggleDiffPreSession",
   "ctrl+x p": "app:cycleDiffBase",
   "ctrl+x space": "app:diffFileListDown"
   ```

   These borrow four diff-panel actions that do nothing in a conversation. Restart Claude Code after editing.
4. **Check it loaded:** `/bm-env` prints `convo-bookmarks 0.1.3 on Claude Code <version>`. "Unknown command" means the mod did not load (see prerequisite 2).
5. **Keep the input box empty** for every chord unless a step says otherwise (see section 6).
6. **A conversation with some history:** at least a dozen of your prompts and several multi-paragraph replies, some with **bold** words.

**Reset between sections:** marks, the reading position and the prompt list are kept per conversation. To start clean, start a new conversation. To clear only the highlight, wait two minutes or send a prompt.

**The debug log** (every `[bm-poc]` line, timestamped) is at `<user dir>/bookmarks/debug/<session id>.log`, where `<user dir>` is `CLAUDE_USER_DIR` or `~/claude`. `/bm-env` shows the session id. To view it:

**cmd.exe**: `type "%USERPROFILE%\claude\bookmarks\debug\<session id>.log"`
**PowerShell**: `Get-Content "$env:USERPROFILE\claude\bookmarks\debug\<session id>.log" -Tail 20`
**POSIX**: `tail -20 ~/claude/bookmarks/debug/<session id>.log`

## High-Value Verification (~5 minutes)

### HV.1: mark and jump with the highlight on a formatted line

Validates: the highlight finds a line containing **bold**, `code` or a link (0.1.2 missed these).

- [ ] **Steps:** select a few words on a line of a reply that contains bold text; `Ctrl+X m`, then `a`; scroll away; `Ctrl+X '`, then `a`.
- [ ] **Expected:** the jump lands on the line; the line has a dark-blue band, the selected words bold yellow with a `«a»` tag. Not a plain `▎ «a» …` quote line at the top of the reply.
- [ ] **Why this matters:** most replies are formatted; without this, marks look broken.

### HV.2: the prompts pane reaches your first prompt

Validates: history back-fill from the transcript, and a jump to a message not drawn since the session started.

- [ ] **Steps:** restart Claude Code (resume the conversation); `Ctrl+X p`; type `1`, then Enter.
- [ ] **Expected:** the list's bottom entry is ` 1) <your first prompt>`. The log has `backfill: N prompts from the transcript via powershell` (Windows) or `via sh` (macOS/Linux). Prompts not drawn since the mod loaded are listed **dim**.
  - In a conversation that was never compacted: the jump lands on prompt #1.
  - If Claude Code has not drawn that message (seen 2026-10-05 for prompts from before a compaction): the view stays put and a toast says `Can't jump there: … Copied "<phrase>": press Ctrl+O, then [ (full conversation), then your terminal's Find (Ctrl+Shift+F or Cmd+F) and paste.`; the log has `scroll -> DENY: nothing drawn under that requestId` and `jump refused; search phrase copied`. Follow the toast: the terminal's find should locate the prompt. (Transcript mode's own `/` search does **not** reach messages from before a compaction; `[` writes the full conversation to the terminal's scrollback, which does. Verified on Windows Terminal, 2026-10-05.)
- [ ] **Why this matters:** without the back-fill the list starts only when the mod loaded; and a refused jump must say so, not silently stay put.

### HV.3: reading position, there and back

Validates: `Ctrl+X Space` sets, goes, and swaps back.

- [ ] **Steps:** select words in an earlier reply, `Ctrl+X Space`; `Ctrl+End`; `Ctrl+X Space`; `Ctrl+X Space`.
- [ ] **Expected:** toast `reading position set: …` with the highlight tagged `` « ` » ``; then a jump to it; then back at the bottom.
- [ ] **Why this matters:** the "keep my place while I check something" loop the feature exists for.

### HV.4: the jump pane lists only what you can jump to

- [ ] **Steps:** with marks `a` and a reading position set, `Ctrl+X '`.
- [ ] **Expected:** a narrow pane: `␣ reading: …` first (the pane starts on it), then `a: <text>`; no unused letters. Enter jumps to the reading position; `a` jumps to mark `a`.

### HV.5: paragraph spacing survives the highlight

- [ ] **Steps:** mark a line that starts a paragraph (a blank line above it), and separately a line that is the **first line** of a reply; jump to each.
- [ ] **Expected:** the blank line above each is still there; nothing runs into the line above. (While a reply's first line is highlighted, its `●` bullet is not drawn: expected.)

## Section 1: highlight and marks

### 1.1 Selection inside a link or `code`
- [ ] **Steps:** mark words that include link text or inline code; jump to the mark.
- [ ] **Expected:** band and yellow on the line; link and code drawn as plain text while highlighted.

### 1.2 Mark pane shows letters in use
- [ ] **Steps:** with marks `a` and `b` set, `Ctrl+X m`.
- [ ] **Expected:** `a: ●` and `b: ●` at full strength, free letters dim (`c: c`), the grid aligned; below it `a ▸ …` and `b ▸ …` with the letters in grey-red. `Esc` closes without marking.

### 1.3 Overwrite a mark
- [ ] **Steps:** select other words, `Ctrl+X m`, `a`.
- [ ] **Expected:** toast `mark a [selection] -> …`; `Ctrl+X '` shows the new text for `a`.

### 1.4 Highlight clears
- [ ] **Steps:** after a jump, wait two minutes; separately, after a jump, send a prompt.
- [ ] **Expected:** the band and yellow are gone both times; the conversation text itself was never changed (copy the line: no `«a»` in it).

## Section 2: prompts pane (`Ctrl+X p`)

### 2.1 Numbering and order
- [ ] **Expected:** newest first; numbers right-aligned (` 9) …`, `21) …`); the number is the prompt's position in the conversation (#1 = first).

### 2.2 Number field: unambiguous numbers jump at once
- [ ] **Steps:** with, say, 25 prompts: `Ctrl+X p`, `3`. Then `Ctrl+X p`, `2`, `1`. Then `Ctrl+X p`, `2`, Enter.
- [ ] **Expected:** `3` jumps immediately (no 30s exist); `2` then `1` jumps to #21; `2` Enter jumps to #2.

### 2.3 Out of range
- [ ] **Steps:** `Ctrl+X p`, `999`, Enter.
- [ ] **Expected:** toast `no prompt #999 (1-N)`; the pane stays open.

### 2.4 Stepping through the list
- [ ] **Steps:** `Ctrl+X p`, Tab, Tab, Shift+Tab, Enter.
- [ ] **Expected:** the focus ring moves down the list and back; Enter jumps to the ringed prompt. Arrow keys scroll the pane (Claude Code's own behaviour), they do not move the ring.

### 2.5 Survives a restart
- [ ] **Steps:** note the top number; send a prompt; restart and resume; `Ctrl+X p`.
- [ ] **Expected:** the list still starts at #1 and includes the prompt just sent. The log has no second `backfill` line for this conversation (it runs once).

## Section 3: reading position (`Ctrl+X Space`)

### 3.1 Same-message selections go, not move
- [ ] **Steps:** with the reading position set, select different words **in the same message**; `Ctrl+X Space`.
- [ ] **Expected:** no `set` toast; it goes to (or back from) the reading position.

### 3.2 Moving it
- [ ] **Steps:** select words in a **different** message; `Ctrl+X Space`.
- [ ] **Expected:** toast `reading position set: <new words>`.

### 3.3 Jump-pane entry keeps the return spot
- [ ] **Steps:** `Ctrl+End`; `Ctrl+X Space` (go there); `Ctrl+X '`, Enter (already there); `Ctrl+X Space`.
- [ ] **Expected:** the last press returns to the bottom, not to the reading position.

### 3.4 Band button
- [ ] **Steps:** click `read` on the band above the prompt, twice.
- [ ] **Expected:** same as the chord: there, then back.

### 3.5 No reading position yet
- [ ] **Steps:** in a new conversation, `Ctrl+X Space` with nothing selected.
- [ ] **Expected:** toast `Select some text, then Ctrl+X Space, to set a reading position`.

## Section 4: modes (#8)

- [ ] **4.1** Vim INSERT mode (`editorMode: vim`): each chord (`Ctrl+X m a`, `Ctrl+X ' a`, `Ctrl+X p 1 Enter`, `Ctrl+X Space`) with an empty input box.
- [ ] **4.2** Vim NORMAL mode (`Esc` first): the same four.
- [ ] **4.3** Transcript mode (`Ctrl+O`): the same four. Note which work.

## Section 5: back-fill details

- [ ] **5.1 Timing:** the log's `backfill` line gives the milliseconds; expect well under a second (about 0.4 s for a two-day conversation on Windows).
- [ ] **5.2 macOS/Linux:** the line says `via sh`.
- [ ] **5.3 Cut-off:** if a conversation's prompts total more than 4 MiB, the line says `CUT OFF at 4 MiB` and the newest prompts may be missing; the next session start tries again.

## Section 6: known limits (record what you see)

- [ ] **6.1 Text in the input box:** type words (don't send), then `Ctrl+X '`. Known: the pane cannot take the keyboard while the input box holds text, so the letter is typed into the box. Record whether the chord itself fires (a `B4: chord …` log line).
- [ ] **6.2 Survey:** when Claude Code's "how is this session" survey occupies the strip above the prompt, try `Ctrl+X Space`. Record whether it works (a log line) or nothing happens.
- [ ] **6.3 Pane width:** the panes ask for 16 columns; Claude Code may give more (`pane was dock, N body columns` in the log). A width you dragged the pane to wins.

## What the automated tests DON'T cover

Everything in sections 1-6: chord delivery, pane focus, selection, scrolling, drawing, spacing, the survey, vim modes, restart behaviour, and how it all feels to use.

## Reporting issues found

1. Note the section and step.
2. Copy the relevant lines from the debug log (they carry timestamps).
3. A screenshot of the terminal if the problem is visual.
4. File an issue referencing this checklist and the version from `/bm-env`.

## Cleanup

- Restore `~/.claude/keybindings.json` from your backup if you do not want the chords kept.
- Remove `CLAUDE_CODE_PLUGIN_DIRS` from `~/.claude/settings.json` if you added it only for this run.
- The debug logs under `<user dir>/bookmarks/debug/` can be deleted.
