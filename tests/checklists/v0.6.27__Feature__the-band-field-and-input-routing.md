## What this is

After `Ctrl+] p` (or `b`) the band now draws a text field of its own for the prompt or bookmark number, in place of a row of digit buttons. This checklist is for a person at a real Claude Code terminal. It checks what the plugin's test kit cannot run:
- where the keyboard is;
- the field's cursor;
- how keybindings resolve;
- the arrow keys.

Run it after any change to the band, its focus handling, or the key table.

## Prerequisites

1. Claude Code 2.1.308 or later, in the fullscreen renderer, with the plugin loaded (`/bm-env` answers).
2. A conversation with at least 5 prompts, so stepping has room. Below, **N** is your newest prompt's number.
3. Your leader bound to `abovePrompt:focus` (this checklist writes `Ctrl+]`).
4. Turn on the keystroke log, so each run can be read back afterwards: type `/bm-diag-keys on`. Turn it off with `/bm-diag-keys off` at the end.
5. To read the log, find the session id with `/bm-env`, then look at the last lines of `bookmarks/debug/<session id>.log` under your data folder.

   **cmd.exe**:
   ```cmd
   powershell -c "Get-Content \"%USERPROFILE%\claude\bookmarks\debug\<session id>.log\" -Tail 30"
   ```

   **PowerShell**:
   ```powershell
   Get-Content "$env:USERPROFILE\claude\bookmarks\debug\<session id>.log" -Tail 30
   ```

   **POSIX**:
   ```bash
   tail -30 "${CLAUDE_USER_DIR:-$HOME/claude}/bookmarks/debug/<session id>.log"
   ```

   (If `CLAUDE_USER_DIR` is set, the data folder is `$CLAUDE_USER_DIR/bookmarks` instead.)

**Reset between sections:** press `Esc` to close the list. Nothing in this checklist writes a file except section 6.2 (it removes a bookmark) and the optional keybinding in section 4.

## High-Value Verification (~5 minutes)

### HV.1 — The band takes the number in its own field

- [ ] **Steps:** with an empty input box, press `Ctrl+]`, then `p`.
- [ ] **Expected:** the prompts pane opens. The band reads `bm prompt k↑ #: … j↓ s★ pin q close (Esc)`, and the cursor is in the band's `#` field.
- [ ] **Why this matters:** every other check starts from the keyboard being in this field. If it isn't, typed keys reach your input box instead.

### HV.2 — Backspace corrects the number, even with an empty input box

- [ ] **Steps:** type `12`, press `Backspace`, type `3`.
- [ ] **Expected:** the band's field shows `13`. The pane's `#` field shows `13`, and the `▶` is on prompt 13. Your input box stays empty.
- [ ] **Why this matters:** this was the bug that started the work: with digit buttons, Backspace did nothing over an empty input box.

### HV.3 — `j` and `k` step, and each step starts fresh

- [ ] **Steps:** clear the field (Backspace until empty), then type `j`, `j`, `k`.
- [ ] **Expected:**
  - The `▶` goes to N, then N-1, then N.
  - After each step the field is empty, with the number shown dim inside it.
  - No letter is left in the field, and no number like `1j5` appears.
- [ ] **Why this matters:** a step writes the number, and a field keeps its cursor when its text is replaced, so this is where the field went wrong twice during development.

### HV.4 — `/words` filters from the band

- [ ] **Steps:** clear the field, type `/` followed by a word from one of your prompts.
- [ ] **Expected:** the pane narrows to the prompts containing it, with "N of M match". Nothing appears in your input box.
- [ ] **Why this matters:** before 0.6.27, `/` from the band went into your draft and ended the list.

### HV.5 — Enter jumps

- [ ] **Steps:** type a prompt number, press `Enter`.
- [ ] **Expected:** the conversation scrolls to that prompt.
- [ ] **Why this matters:** a jump must run while the field's own handler is running, or Claude Code refuses it as "not person-initiated".

### HV.6 — The fallback brings back the digit buttons

- [ ] **Steps:** `/config`, open **▸ Bookmarks**, set **Typing a list number** to `buttons`. Close `/config`, then `Ctrl+]`, `p`.
- [ ] **Expected:** the band shows `prompt # _ (1-N)` and the buttons `0`-`9`, `.`, `k↑`, `go (Enter)`, `j↓`, with no field. Set it back to `auto`, and the field returns.
- [ ] **Why this matters:** if a future Claude Code build breaks the field, this setting is the way back without a new plugin version.

## Section 1: Typing in the field

### 1.1 Over a draft

- [ ] **Steps:** type some text in your input box (don't send it). `Ctrl+]`, `p`, type `5`, Backspace, `4`.
- [ ] **Expected:** the field shows `4`, and the pane follows. Your draft is unchanged.

### 1.2 A number then a step key

- [ ] **Steps:** type `12j`.
- [ ] **Expected:** the `▶` moves to 11 (one step older than 12). The field is empty, with `11` dim.

### 1.3 Pin with `*`

- [ ] **Steps:** type `*` then a prompt number, then Enter.
- [ ] **Expected:** that prompt pins (or unpins) and moves to the pinned group at the top of the pane.

### 1.4 `s` pins the prompt under the `▶`

- [ ] **Steps:** step to a prompt with `j`, then type `s`.
- [ ] **Expected:** the prompt under the `▶` pins or unpins. The band stays open.

## Section 2: Tab and Shift+Tab

### 2.1 Tab steps

- [ ] **Steps:** with the field focused, press `Tab` three times, then `Shift+Tab` once.
- [ ] **Expected:** the `▶` moves down three, then up one. The cursor stays in the band's field throughout.

## Section 3: Enter and the end of the list

### 3.1 Enter on an empty field after a step

- [ ] **Steps:** clear the field, type `j` (the field shows N dim), press `Enter`.
- [ ] **Expected:** the jump goes to prompt N, the dim number.

### 3.2 Enter with no number

- [ ] **Steps:** `Ctrl+]`, `p`, then `Enter` straight away.
- [ ] **Expected:** the list closes, and the band returns to its bar.

### 3.3 `q` and `Esc`

- [ ] **Steps:** `Ctrl+]`, `p`, type `q`. Then `Ctrl+]`, `p`, press `Esc`.
- [ ] **Expected:** both close the list without a jump.

## Section 4: Up and Down (optional keybinding)

### 4.1 Add the binding

- [ ] **Steps:** add this entry to the `bindings` array in `~/.claude/keybindings.json`, beside your leader's, and start a new session:

  ```json
  { "context": "AbovePromptInput", "bindings": { "up": "abovePrompt:previous", "down": "abovePrompt:next" } }
  ```

### 4.2 Up first, then Down

- [ ] **Steps:** `Ctrl+]`, `p`, press `Up` first, then `Down` twice.
- [ ] **Expected:** each press steps the `▶`: Up first steps up, not along the band's buttons. The cursor stays in the band's field.

### 4.3 Quick presses

- [ ] **Steps:** press `Down` and `Up` quickly, about ten times.
- [ ] **Expected:** every press steps, and the keyboard never leaves the band.
- [ ] **Check:** the log has `band arrow -> …` lines and no `DENY no element of bookmarks is drawn under that key`.

### 4.4 Without the binding

- [ ] **Steps:** remove the entry and start a new session; `Ctrl+]`, `p`, press `Up` and `Down`.
- [ ] **Expected:** nothing happens; `j`/`k` and Tab still step. (A band text field keeps the arrows to itself without the binding.)

## Section 5: When the keyboard leaves

### 5.1 The wait ends on its own

- [ ] **Steps:** `Ctrl+]`, `p`, type `3`, then wait about 15 seconds without typing.
- [ ] **Expected:** the band returns to its bar. The pane stays as a readable list or closes, depending on "Prompts or bookmarks list after you pick a row".

### 5.2 A click into the input box

- [ ] **Steps:** `Ctrl+]`, `p`, then click in your input box and type.
- [ ] **Expected:** your typing goes to the input box. The band steps back, and the log says `band lost the keyboard`, once, not every 400 ms.

## Section 6: The bookmarks list

### 6.1 The same field

- [ ] **Steps:** `Ctrl+]`, `b` (in a conversation with at least one bookmark).
- [ ] **Expected:** the band reads `bm bookmark k↑ #: … j↓ h … l c d q (Esc)`, with the cursor in the field. `j`/`k` step, and `h`/`l` change the group (yours, Claude's, all).

### 6.2 Remove by number

- [ ] **Steps:** type a bookmark's number then `d` (for example `1d`).
- [ ] **Expected:** the toast says `removed bookmark: …`, the row leaves the list, and the field is empty again.
- [ ] **Check:** `/bm-check` reports nothing amiss. The bookmarks file keeps a tombstone in the bookmark's place.

## What the automated tests DON'T cover

- **Where the keyboard is.** The kit doesn't run a plugin's own focus moves, so whether the cursor sits in the band's field, and stays there, is checked only here (HV.1, 2.1, 4.2, 4.3).
- **The field's cursor.** A field the plugin rewrites keeps its cursor where it was, and the kit's field has no cursor. HV.3 and 1.2 are the checks.
- **Keybindings.** The Up/Down entry is resolved by Claude Code before the field sees the key; the kit doesn't load `keybindings.json` (section 4).
- **The jump's scroll.** The kit doesn't run the plugin's own scroll, so HV.5 and 3.1 are the only proof a jump lands.
- **The probe's timing.** The 400 ms keyboard probe and the 15 s wait run on real clocks (section 5).

## Reporting issues found

1. Note the section and step number.
2. Copy the last 30 lines of the debug log (Prerequisites, step 5). The keystroke log shows each key, focus move and step.
3. File an issue referencing this checklist and version 0.6.27.

## Cleanup

1. `/bm-diag-keys off`.
2. If you set **Typing a list number** to `buttons`, set it back to `auto`.
3. Keep or remove the Up/Down keybinding as you prefer; the plugin never writes that file.
