# Human Test Checklist: a continued conversation keeps its bookmarks

**Target version:** 0.7.34 (the build spans 0.7.30 to 0.7.34)
**Ships with commit:** `feat(adopt): on by default, with a /config row to turn it off; the jumplist comes along (v0.7.34)`
**Companion automated tests:** core `tests/core/lineage.test.ts` (15, over the 7 cases in `tests/fixtures/session-lineage/`), `tests/core/adopt.test.ts` (8); kit `plugin/tests/lineage.test.ts` (4), `plugin/tests/continuation.test.ts` (3), `plugin/tests/adopt.test.ts` (8).

## What this is

Claude Code sometimes carries a conversation on under a new session id: `/branch`, `--fork-session`, a `/rewind` that continues, a background hand-off. Before this build, the new id started with no bookmarks, marks, pins or jumplist, and links into the copied history refused to jump. This checklist is what a person runs to see, in a real Claude Code, that the new id now finds its earlier sessions and copies their data in once, and that the earlier files are never touched. The kit fakes the transcript, the store and the timing; this does not.

## Prerequisites

1. Claude Code with this plugin at 0.7.34 or later (`/bm-env` names the version).
2. A conversation with a few bookmarks, a mark or two (`<leader> m a` on a line) and a pin, and at least one jump made (so it has a jumplist). Call it **A**.
3. A backup of the plugin's data before you start. The copy writes only the new id's file, but a backup costs nothing:

   **cmd.exe**: `xcopy /E /I "%USERPROFILE%\claude\bookmarks" "%TEMP%\bookmarks-backup"`
   **PowerShell**: `Copy-Item -Recurse "$env:USERPROFILE\claude\bookmarks" "$env:TEMP\bookmarks-backup"`
   **POSIX**: `cp -R ~/claude/bookmarks /tmp/bookmarks-backup`

4. Note A's session id (`/bm-env`, or the file name under `~/claude/bookmarks/sessions/`), and take a hash of its file:

   **cmd.exe**: `certutil -hashfile "%USERPROFILE%\claude\bookmarks\sessions\<A>.json" SHA256`
   **PowerShell**: `Get-FileHash "$env:USERPROFILE\claude\bookmarks\sessions\<A>.json"`
   **POSIX**: `sha256sum ~/claude/bookmarks/sessions/<A>.json`

The log for a conversation is `~/claude/bookmarks/debug/<session id>.log` (view it with `type`, `Get-Content` or `cat`).

## High-Value Verification (~5 minutes)

### HV.1 -- A branch brings its bookmarks

Validates: the lineage scan and the copy, end to end.

- [ ] **Steps:** in A, run `/branch`. In the new conversation (**B**), wait a few seconds, then open the bookmarks pane (`<leader> b`).
- [ ] **Expected:** A's bookmarks are listed, with A's numbers. B's log has `[bm] lineage of <B8>: <A8> (...)` and `[bm] adopt: N copied into <B8> from <A8>`.
- [ ] **Why this matters:** this is the whole feature; without it B starts empty.

### HV.2 -- Marks, the reading position and pins came too

- [ ] **Steps:** in B, `<leader> '` then a letter A had set; `<leader> Space Space` (the reading position); open the prompts pane and look for A's pin.
- [ ] **Expected:** each goes where it went in A; the pin shows.
- [ ] **Why this matters:** marks and pins live in the same file as bookmarks; a partial copy would show here.

### HV.3 -- A's file is untouched

- [ ] **Steps:** hash A's file again (Prerequisites, step 4).
- [ ] **Expected:** the same hash as before.
- [ ] **Why this matters:** the earlier conversation is only ever read; a write there would change another conversation's bookmarks.

### HV.4 -- An old link still works from B

- [ ] **Steps:** in B, press a bookmark link Claude wrote in A (it names A's id), or ask Claude for `bm:<A8>.1`.
- [ ] **Expected:** it jumps to the message in B.
- [ ] **Why this matters:** copied bookmarks keep A's id so these links stay good; this proves the pair works.

### HV.5 -- It happens once

- [ ] **Steps:** in B, remove one of the copied bookmarks (in the bookmarks pane, its number then `d`). Restart B (`/exit`, then `claude --resume <B>`).
- [ ] **Expected:** the removed bookmark does not come back; the log has no second `adopt:` line for B.

## Section 1: details

### 1.1 Own bookmarks win
- [ ] In B, before or after the copy, bookmark a message A had also bookmarked, with a different label. **Expected:** one row for it, with B's label; the others keep A's numbers, and a number B used for its own bookmark is not taken by a copy (the copy gets the next free one).

### 1.2 The jumplist
- [ ] In B, before making any jump, press back (`<leader> o`). **Expected:** it walks A's jumplist. A conversation that has jumped already keeps its own jumplist.

### 1.3 Turning it off
- [ ] `/config`, open **Bookmarks**, set "Bring bookmarks into a continued conversation" to `false`. `/branch` from A again. **Expected:** the new conversation's bookmarks pane is empty; no `adopt:` line in its log. Set it back to `true` afterwards.

### 1.4 A chain
- [ ] Branch B again (**C**). **Expected:** C's log names both earlier ids (oldest first in the lineage line); C has A's and B's bookmarks, B's copy of each place kept.

### 1.5 The first seconds
- [ ] Open B's bookmarks pane the moment B starts. **Expected:** it may be empty for a second or two and fill once the scan finishes (the scan runs in the background; it takes 1-4 s on a large transcript). Report it if it never fills.

## What the automated tests DON'T cover

- A real `/branch`, `--fork-session` or `/rewind` transcript (the kit's are hand-written rows).
- The real `sh`/`grep` scan on a large transcript, and its timing on a slow machine.
- The real plugin store and a hot reload landing mid-copy.
- What the panes look like while the copy lands (1.5).
- A conversation whose earlier sessions are on another machine (it copies nothing; links still lead here).

## Reporting issues found

Note the step, attach B's log (`~/claude/bookmarks/debug/<B>.log`) and `/bm-env`'s output, and file an issue referencing this checklist and #39.

## Cleanup

Restore the backup if anything went wrong (copy `bookmarks-backup` back over `~/claude/bookmarks`, after moving the current folder aside). Remove the backup when done: `rmdir /S /Q "%TEMP%\bookmarks-backup"` (cmd), `Remove-Item -Recurse "$env:TEMP\bookmarks-backup"` (PowerShell), `rm -rf /tmp/bookmarks-backup` (POSIX).
