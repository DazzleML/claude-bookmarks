# Human Test Checklist: The prompts pane shows where you are (v0.4.0)

**Target version:** 0.4.0
**Ships with commit:** v0.4.0: the prompts pane shows where you are; queued prompts in the list (TBD at commit)
**Ships after:** v0.3.5, `9f56604`
**Companion automated tests:** 18 new under `plugin/hooks/core/`: `view-position.test.ts` (10, the rule that picks the nearest prompt) and `prompt-rows.test.ts` (8, which transcript rows are prompts). 50 in all with `node --test plugin/hooks/core/*.test.ts`. `tsc -p plugin --noEmit` and `claude plugin validate ./plugin` must pass; `validate` lists `bookmarks.viewRev` among the state reads.

## What this is

v0.4.0 makes the prompts pane (`Ctrl+] p`) answer "where am I?": the prompt nearest your view has its number drawn in yellow, the list opens scrolled so that row is in the middle, and the yellow follows you as you scroll while the pane is open. It also fixes two things about what the list holds: messages typed while Claude was working (which Claude Code queues and stores differently) are now listed, and rows that are not prompts (interruption notices, slash-command echoes, the `!` shell's input and output, compaction summaries) are no longer. Every one of these can only be seen in a live terminal with a real conversation on screen, which is why this document exists. Windows is the author's platform; macOS and Linux items are marked untested.

The pure rule under the yellow row is tested: the exchange (a prompt and the replies after it) that takes the most screen lines wins, and when two are close (the smaller holds at least 60% of the larger) the earlier one does, so you have context above as well as below. What the tests cannot see is what Claude Code actually reports as "on screen", when, and how the pane looks.

## Prerequisites

1. Claude Code 2.1.295 or later with the plugin loaded in a shell-started session (`CLAUDE_CODE_PLUGIN_DIRS` pointing at the checkout, or the installed plugin). A daemon-hosted session may not load the plugin.
2. `/bm-env` reports `bookmarks 0.4.0`.
3. **A conversation long enough to scroll**: at least 20 prompts, several with replies longer than a screen. A fresh conversation will not show most of this. Use a throwaway conversation you do not mind reading from, or any conversation of your own: nothing here changes a conversation.
4. **State isolation.** The feature writes two things: the prompts list, key `prompts:<session id>` in Claude Code's plugin store (`~/.claude/plugins/store/bookmarks_inline-<id>.json`), and a `backfilled3:<session id>` flag beside it. The list is rebuilt from the transcript once when a conversation starts under 0.4.0. Nothing in your conversation files is written. Read the store only; never edit it while a session is open.
5. **The log.** Turn on the echo with `/bm-debug on` (this conversation only). The plugin also writes `~/claude/bookmarks/debug/<session id>.log` (or under `$CLAUDE_USER_DIR` when set). Three line kinds matter here:

   | Line | Meaning |
   |---|---|
   | `nearest prompt moved: <a> -> <b> \| on screen (id:order:lines) …` | The yellow row changed, and what the plugin saw on screen when it did |
   | `prompts pane centred on <id> -> ok (try N)` | The list scrolled to the yellow row when it opened |
   | `pane follow to <id> -> ok` | The list slid to keep the yellow row showing |

   To read the tail (pick your shell; replace `<session id>` with the id `/bm-env` prints):

   **cmd.exe**:
   ```cmd
   powershell -NoProfile -Command "Get-Content \"$env:USERPROFILE\claude\bookmarks\debug\<session id>.log\" -Tail 20"
   ```

   **PowerShell**:
   ```powershell
   Get-Content "$env:USERPROFILE\claude\bookmarks\debug\<session id>.log" -Tail 20
   ```

   **POSIX**:
   ```bash
   tail -n 20 "$HOME/claude/bookmarks/debug/<session id>.log"
   ```

6. **Reset between sections:** `Esc` closes any pane; `Ctrl+End` (or scrolling to the bottom) returns the view to the newest message. Nothing else accumulates.

## High-Value Verification (~5 minutes)

**If you only have 5 minutes**, run these five. Each is covered in detail below.

### HV.1 — The yellow row is where you are

Validates: the nearest-prompt rule, fed by what Claude Code reports on screen.

- [ ] **Steps:**
  1. Scroll up until a prompt you recognise is near the top of the screen, with its reply filling the rest.
  2. `Ctrl+] p`.
- [ ] **Expected:** that prompt's number is yellow and bold; the legend under the list reads `yellow = nearest to your view`; every other number is plain (dim when its message is not on screen).
- [ ] **Why this matters:** this is the feature. A wrong row here means the list is lying about the conversation.

### HV.2 — The list opens on the yellow row

Validates: centre-on-open and its retries.

- [ ] **Steps:**
  1. `Esc`. Scroll far up, to the first quarter of the conversation.
  2. `Ctrl+] p`.
- [ ] **Expected:** the list is already scrolled so the yellow row is near the middle of the pane, not at the newest prompt. The log has `prompts pane centred on … -> ok (try N)` with N from 0 to 3.
- [ ] **Why this matters:** without it the yellow row is off the bottom of the list and nobody sees it.

### HV.3 — The yellow follows the view

Validates: the dynamic update and the follow scroll.

- [ ] **Steps:**
  1. With the pane open, scroll the conversation up a few screens, slowly.
- [ ] **Expected:** the yellow moves from row to row as earlier exchanges fill the screen; the list slides only when the yellow row would leave it. Log: a `nearest prompt moved` line per change, each followed by `pane follow to … -> ok`.
- [ ] **Why this matters:** a static highlight is a snapshot; the follow is what makes the pane a position indicator.

### HV.4 — A message typed while Claude was working is in the list

Validates: queued prompts, live and from the transcript.

- [ ] **Steps:**
  1. Ask Claude something that takes a while (read a large file, run tests). While it works, type a second message and send it.
  2. When the turn ends, `Ctrl+] p`.
- [ ] **Expected:** both messages are rows, in order, the second with its own number. Its text is your words, not the `<system-reminder>` prose Claude Code wraps around a queued message.
- [ ] **Why this matters:** before 0.4.0 such a message was simply missing, and every number after it was one too low against what you remembered sending.

### HV.5 — No row that is not a prompt

Validates: the prompt filter, live and in the back-fill merge.

- [ ] **Steps:**
  1. Run `! git status` (the `!` shell), then a slash command such as `/bm-env`, then interrupt Claude once with `Esc` while it is replying.
  2. `Ctrl+] p` and read the rows around the newest ones.
- [ ] **Expected:** none of `<bash-input>`, `<bash-stdout>`, `<command-message>`, `<command-name>`, `<local-command-stdout>` or `[Request interrupted by user` appears as a row. The numbers run without gaps.
- [ ] **Why this matters:** in the author's conversation eight such rows sat in the list, so every number past them was eight too high and the yellow row sat on the wrong prompt.

## Section 1: The yellow row (~5 min)

### 1.1 Between two prompts, the earlier wins

- [ ] **Steps:**
  1. Scroll so a long reply fills most of the screen and the *next* prompt shows in the bottom two or three lines.
  2. `Ctrl+] p`.
- [ ] **Expected:** the prompt *above* the long reply is yellow, not the one peeking in at the bottom.
- [ ] **Check:** the `nearest prompt moved` line lists the reply with many lines (`…:NL` with N large) and the bottom prompt with few.

### 1.2 Two exchanges sharing the screen

- [ ] **Steps:**
  1. Scroll so one short exchange ends in the upper half and the next begins in the lower half, roughly equal.
  2. `Ctrl+] p`.
- [ ] **Expected:** the earlier one is yellow (within 60% of each other, the earlier wins: context above and below).

### 1.3 A thin sliver does not win

- [ ] **Steps:**
  1. Scroll so one or two lines of the previous exchange remain at the very top and the rest of the screen is the next exchange.
- [ ] **Expected:** the *later* exchange's prompt is yellow.

### 1.4 At the bottom

- [ ] **Steps:**
  1. `Ctrl+End`, then `Ctrl+] p`.
- [ ] **Expected:** the newest prompt is yellow when its exchange fills the screen; if the newest reply is short and the one before fills most of the screen, the one before is yellow (1.1 again).

### 1.5 Above the first prompt

- [ ] **Steps:**
  1. Scroll to the very top of a conversation whose first rows are not prompts (a resumed or compacted one begins with a summary).
  2. `Ctrl+] p`.
- [ ] **Expected:** no yellow row and no legend, rather than a wrong row.

### 1.6 Colour on your terminal

- [ ] **Steps:** look at the yellow number on your terminal's theme.
- [ ] **Expected:** readable against the pane background. Note the terminal and theme if it is not (this feeds the theming issue; the pane cannot yet know your background).

## Section 2: Opening and following (~5 min)

### 2.1 Centre-on-open from far up

- [ ] As HV.2. Also open the pane while at the bottom: the list shows the newest rows (nothing to centre away from).

### 2.2 The retry

- [ ] **Steps:** open the pane from far up five times (`Ctrl+] p`, `Esc`, repeat).
- [ ] **Expected:** every open lands on the yellow row. The log shows `-> ok (try 0)` or `(try 1)` for most; a `(try 3)` is allowed; a `DENY` after try 3 is a finding (note the terminal size and how long the conversation is).

### 2.3 Follow keeps the row in view, and no more

- [ ] **Steps:** with the pane open, scroll the conversation up one screen at a time.
- [ ] **Expected:** the list does not move while the yellow row is still visible; when the yellow would leave the top of the list, the list slides just enough. No jumping to the top or bottom of the list.

### 2.4 Follow pauses while you type a number

- [ ] **Steps:** `Ctrl+] p`, type `1` (do not press Enter), then scroll the conversation.
- [ ] **Expected:** the yellow still updates, but the list does not slide while a number is pending; `Enter` jumps to prompt #1 as before. `Esc` clears the number.

### 2.5 A reply streaming in does not steal the yellow

- [ ] **Steps:**
  1. Scroll up a few screens and open the pane.
  2. Send a prompt and let Claude reply at length while you stay scrolled up.
- [ ] **Expected:** the yellow stays on the exchange you are reading for the whole reply; it does not jump to the newest prompt. Sending the prompt does not blank the yellow.
- [ ] **Check:** the log's `on screen` listing during the reply names the growing message only; no `nearest prompt moved` to the newest number.

### 2.6 Clicking the input box keeps the pane open

- [ ] **Steps:** open the pane, then click in Claude Code's input box with the mouse and type a character.
- [ ] **Expected:** the pane stays open, the character lands in the input box. The mark pane and jump pane (`Ctrl+] m`, `Ctrl+] '`) behave the same way. The band's number field, if one was pending, is cleared.

### 2.7 Jumping from the list

- [ ] **Steps:** open the pane, type a number, `Enter`.
- [ ] **Expected:** the view jumps; on reopening the pane that prompt is yellow.

## Section 3: What the list holds (~5 min)

### 3.1 The queued message, live

- [ ] As HV.4. Also send two queued messages in one turn: both appear, in order.

### 3.2 The queued message, from the transcript

- [ ] **Steps:**
  1. In a conversation that holds queued messages from before 0.4.0, start a new session with `claude --resume` (or `/resume`).
  2. `Ctrl+] p`.
- [ ] **Expected:** the queued messages are rows at their place in the conversation. The log has a `backfill: N prompts from the transcript via <sh+grep|powershell> in <ms> ms` line, once; a second start of the same conversation has none.

### 3.3 Non-prompt rows, from the transcript

- [ ] **Steps:** same conversation as 3.2, after the back-fill.
- [ ] **Expected:** no interruption, command-echo, `!` shell or compaction-summary rows; numbers run without gaps; the yellow row agrees with the screen (HV.1) in the second half of the conversation as well as the first.

### 3.4 Both row-reading paths give the same rows (Windows)

Validates: the PowerShell script and the `sh` + `grep` pipeline agree now that both look for queued rows.

- [ ] **Steps** (PowerShell; `<jsonl>` is the conversation file under `~/.claude/projects/<folder>/<session id>.jsonl`, and `<plugin>` the plugin folder):

  ```powershell
  (powershell -NoProfile -NonInteractive -ExecutionPolicy Bypass -File "<plugin>\hooks\scripts\user-rows.ps1" -Path "<jsonl>" -UserRow '"type":"user"' -QueuedRow '"type":"queued_command"' -ToolResultRow '"type":"tool_result"' | Measure-Object -Line).Lines
  ```

  **POSIX** (also Git Bash on Windows):
  ```bash
  grep -F -e '"type":"user"' -e '"type":"queued_command"' "<jsonl>" | grep -vF '"type":"tool_result"' | wc -l
  ```

- [ ] **Expected:** the same count from both. (On the author's 2026-10-11 conversation both gave 513.)

### 3.5 A prompt that mentions a tag is kept

- [ ] **Steps:** send a prompt whose text *contains* `<bash-input>` but does not start with it, for example `Why does <bash-input> show in the list?`.
- [ ] **Expected:** it is a row. The filter looks at a row's opening only.

## Section 4: Platforms

### 4.1 Windows Terminal (tested by the author)

- [ ] Sections 1 to 3 pass at full screen and at a half-width window.

### 4.2 macOS Terminal / iTerm2 — **untested**

- [ ] HV.1 to HV.5. Note whether `yellow` is readable on the default light theme (1.6).

### 4.3 Linux (any terminal) — **untested**

## What the automated tests DON'T cover

- What Claude Code reports as "on screen", and when: the reports arrive for drawn messages and, on a scroll, for the messages at the viewport's edges only; a message that leaves in one jump is never reported gone. The weighing rule is only as good as these inputs.
- The 150 ms debounce and the 60/180/420/900 ms centre retries: timing against a real engine.
- The id relation between a drawn message and its transcript uuid (the first four groups match, the last differs), which the pane relies on to place what is on screen.
- The `$.ui.scroll` refusals (`DENY`) and whether `block: 'nearest'` slides the least.
- Colour and boldness as rendered by a terminal, on light and dark themes.
- The two row-reading paths against a real conversation file, including one over 4 MiB of matching rows (the plugin caps output there; the log says `CUT OFF`).
- Mouse focus moving to the input box while a pane is open.
- Hot reload: the plugin reloads a couple of minutes after a save; module state (the last yellow row, pending centre) resets.

## Reporting issues found

1. Note the section and step number.
2. Copy the last 20 lines of the debug log (prerequisite 5) and the `on screen` listing from the relevant `nearest prompt moved` line.
3. Note the terminal, its size, and whether the conversation was resumed.
4. File an issue at https://github.com/DazzleML/claude-bookmarks/issues referencing this checklist and v0.4.0.

## Cleanup

Nothing to restore. `/bm-debug off` turns the echo off again; the debug log file can stay or be deleted (it is recreated on demand). The store keys `prompts:<session>` and `backfilled3:<session>` are the feature's normal state and should be left.
