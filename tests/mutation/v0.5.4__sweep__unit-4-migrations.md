## Triage

- **M4, killable.** The fixture's three own records all spelt the same path once slashes were normalised, so the sort direction never mattered. Now one record carries the path a `/cd` would give, and the majority rule is pinned.
- **M6, killable.** The copied record was outnumbered 3 to 1, so counting it changed nothing. A focused test now has one own record against two copies.
- **M12, don't-care.** The opened conversation migrating first matters only if the sweep is interrupted between files (the opened one is then safe); within one start every register is migrated before the first load, so no test can see the order without failure injection in the harness. Recorded in `equivalents.md` with that reasoning; the preference stands in the code.
- **M13, killable.** The kit's clock is fixed, so a second snapshot in the same start landed on the same folder name and left one manifest; counting the manifest's writes sees it.
- **M14, killable.** The ladder's intermediate state is invisible on disk once `done` is written; the order of the engine's write calls is the record, and the test now reads it.

## Caveats

A kill proves the suite noticed *this* change, not that it tests the right thing. **A clean sweep is evidence about the mutations tried, not proof of suite completeness.** The red-green audit of the unit's own 11 tests (6 anchors / 5 guards, `scratchpad/redgreen/audit4.py`) is the separate check that those tests are attached to the change; the live check is the data root after the next start (`~/claude/bookmarks/backups/`).
