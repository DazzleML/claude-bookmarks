# Human Test Checklist: the key table, the band-button toggle and deleting a mark

**Target version:** 0.6.24 (the units shipped as 0.6.1-0.6.5, 0.6.23 and 0.6.24; first written at 0.6.20 with the last two pending)
**Ships with commit:** `docs(keys): the keymap's docs, the checklist's /config steps (v0.6.24)` and the slice-A commits before it on `dev`
**Companion automated tests:** 36 core tests in `tests/core/keys.test.ts` (22), `tests/core/keymap.test.ts` (8) and `tests/core/keymap-config.test.ts` (6); 31 plugin tests in `plugin/tests/band.test.ts` (8), `keymap-config.test.ts` (8), `pane-keys.test.ts` (6), `deletion.test.ts` (5) and `filter.test.ts` (4); the orphan-record row of `plugin/tests/check.test.ts`

## What this is

A hand-run walk through what the automated tests cannot see: the live band drawn by Claude Code, its hotkeys and buttons, the `/config` menu, a real register file under your own folder, and a plugin that reloads while you work. It covers all six units of the keys work (legend below). Anyone with Claude Code and this plugin installed can run it; no project-private document is needed.

## Legend

| Code | Meaning |

| A2 | The keymap layer: a pure module that applies a person's key choices to the table and reports problems |

## Prerequisites

1. Claude Code 2.1.303 or later with the bookmarks plugin installed, in a terminal at least 80 columns wide.
2. **Isolate the data.** The plugin keeps its files under `~/claude/bookmarks`; `CLAUDE_USER_DIR` replaces `~/claude`. Start the Claude Code session you test in from a shell where it points at a scratch folder, so no real register is touched:

   **cmd.exe**:
   ```cmd
   set CLAUDE_USER_DIR=%TEMP%\bm-checklist
   mkdir %CLAUDE_USER_DIR%
   claude
   ```

   **PowerShell**:
   ```powershell
   $env:CLAUDE_USER_DIR = "$env:TEMP\bm-checklist"
   New-Item -ItemType Directory -Force $env:CLAUDE_USER_DIR | Out-Null
   claude
   ```

   **POSIX**:
   ```bash
   export CLAUDE_USER_DIR=/tmp/bm-checklist
   mkdir -p "$CLAUDE_USER_DIR"
   claude
   ```
3. In that session, send three short prompts so the prompts pane has rows, and get at least one reply with a few lines so marks have a target.
4. **Reset between sections:** `/bm-delmarks a b c` clears the letters used below; `q` closes any open pane; `Esc` leaves the band.

The leader is `Ctrl+]`. "The band" is the row of buttons above the input box after the leader; "the pane" is the list that opens beside the chat.

## High-Value Verification (~5 minutes)

### HV.1 — The prompts pane's field takes the table's keys (A1)

Validates: the pane's `#` field routes `/`, `*` and digits through the key table rather than its own literals.

- [ ] **Steps:**
  1. `Ctrl+]`, then `p`. The prompts pane opens and the band shows the number row.
  2. Type `/` then a word from one of your prompts, then `Enter`.
  3. Type `*2` then `Enter`.
- [ ] **Expected:** step 2 filters the list to prompts holding the word and the band's hint still names the keys; step 3 pins prompt 2 (a `★` section appears at the top).
- [ ] **Why this matters:** A1 moved these keys out of the pane's own code. If the field stops routing, `/` types a literal slash into the number field and nothing filters.

### HV.2 — `j`/`k` step by the operation, not the letter (A1)

- [ ] **Steps:** with the prompts pane open, press `j` three times, then `k` once.
- [ ] **Expected:** the `▶` moves down three rows and up one; the band's hint shows `j`/`k` beside "older/newer".
- [ ] **Why this matters:** the band row selects its buttons by the step operation; a wrong selection draws the right letter on the wrong button.

### HV.3 — The button toggles, the key does not (A4)

- [ ] **Steps:**
  1. `Ctrl+]`, `p`: the pane opens.
  2. Click the `prompts` button on the band.
  3. `Ctrl+]`, `p` again (the pane is open now): press `p` once more in the band's field.
- [ ] **Expected:** step 2 closes the pane and the band goes back to its idle row; step 3 leaves the pane open (the key never toggles).
- [ ] **Why this matters:** the toggle is a mouse affordance only; a key that toggled would close the pane the person just asked for.

### HV.4 — `d` clears, `D` forgets (A5)

- [ ] **Steps:**
  1. `Ctrl+]`, `m`, `a`: letter `a` marks the last reply. `/bm-marks` shows `a`.
  2. `Ctrl+]`, `d`, `a`.
  3. `Ctrl+]`, `m`, `b`; then `Ctrl+]`, `D`, `b`.
- [ ] **Expected:** after step 2 `/bm-marks` shows `a` pointing at nothing (its history kept; `/bm-marks a` still lists the old target); after step 3 `b` is gone entirely from `/bm-marks`, and the register file under `$CLAUDE_USER_DIR/bookmarks/sessions/<session id>.json` holds no record for it.
- [ ] **Why this matters:** `d` and `D` are the two deletions with different promises; if `D` left a record, `/bm-check` would report an orphan the person never made.

### HV.5 — The help explains every key you can press (A1/A2)

- [ ] **Steps:** `Ctrl+]`, `?`.
- [ ] **Expected:** one line per command, each key named once, `d` and `D` among them with their letter argument; `q` returns to the bar.
- [ ] **Why this matters:** the help is drawn from the same table as the handlers; a key in one and not the other is the defect the table exists to prevent.

### HV.6 — Your own key, from /config (A3)

- [ ] **Steps:** `/config`, search `bookmarks`, set **Keys: show the key rows** to `shown`, set **Keys: prompts** to `l`; close `/config`; `Ctrl+]`, `l`.
- [ ] **Expected:** the rows appeared without reopening the menu; the `prompts` button presses with `l`, and `l` opens the prompts pane. Reset the row to empty.
- [ ] **Why this matters:** this is the one surface where a person's choice reaches every reader of the key table; a reader left on the defaults shows the old key on the bar while the field takes the new one.

## Section 1: the band's idle row (A1, A2)

### 1.1 One button per shown command, `?` last

- [ ] **Steps:** `Ctrl+]`.
- [ ] **Expected:** the buttons read `mark`, `jump`, `prompts`, `read`, `bookmarks`, `P` (promote), `?` in that order; no button repeats a key; `o`, `i`, `q` have no button (they are typed).
- [ ] **Check:** a hotkey underline or marker appears only on buttons whose key is a lowercase letter or digit; `'` (jump's first key) and `Space` (read's) carry none.

### 1.2 A stray key reminds, once

- [ ] **Steps:** `Ctrl+]`, then `x`.
- [ ] **Expected:** a one-line hint naming `?` for the list; a second stray key gives the same hint, not an action.

## Section 2: the panes hold the table's keys (A1)

### 2.1 Footnote numbers in the field

- [ ] **Steps:** prompts pane open; type the number of a prompt that shows `… 1 footnote` beneath it, then `.1`, then `Enter`.
- [ ] **Expected:** the jump lands on the footnote (the notice or command the prompt carried), not the prompt.

### 2.2 The bookmarks pane: `h`/`l` groups, `d` removes

- [ ] **Steps:**
  1. Make a bookmark: click `⚓`-less text? No: type `/bm-mark` is not it either. Use `Ctrl+]`, `m`, `c`, then `/bm-promote c` (the mark becomes a bookmark on your list).
  2. `Ctrl+]`, `b`; press `l` then `h`.
  3. With `▶` on the new bookmark, press `d`.
- [ ] **Expected:** step 2 moves between your group, Claude's and all; step 3 removes the bookmark and the row disappears; `/bm-check` reports nothing about it.

### 2.3 `Esc` and `q`

- [ ] **Steps:** open either pane; `Esc`. Open again; type `q` in the pane's `#` field.
- [ ] **Expected:** both close the pane without a jump; the band returns to its idle row.

## Section 3: the toggle (A4)

### 3.1 The mark pane

- [ ] **Steps:** `Ctrl+]`, `m` with a letter pending shows the marks pane; click `mark` on the band.
- [ ] **Expected:** the pane closes; the pending letter is dropped (no mark made).

### 3.2 The field-only band

- [ ] **Steps:** `/config`, set the band to `field`; `Ctrl+]`, `p`; `Ctrl+]`, `p` again.
- [ ] **Expected:** with no buttons there is nothing to click; the key opens and leaves open, never closes. Set the band back to `full`.

## Section 4: the deletion family against the real file (A5)

### 4.1 `D` with a history

- [ ] **Steps:** `Ctrl+]`, `m`, `a` on one reply; send a prompt; `Ctrl+]`, `m`, `a` on the new reply (the letter moves, the history grows); `Ctrl+]`, `D`, `a`.
- [ ] **Expected:** `/bm-marks a` no longer lists the letter; in the register file the earlier target stays as a record (the history is more than one entry, so the record is kept and the letter's current entry leaves without a tombstone).

### 4.2 `d` on a letter that is already clear

- [ ] **Steps:** `Ctrl+]`, `d`, `z`.
- [ ] **Expected:** a hint that `z` holds nothing; no file changes (check the file's modified time).

### 4.3 `/bm-check` after the section

- [ ] **Steps:** `/bm-check`.
- [ ] **Expected:** "nothing to report", or a line naming an orphan record if a step above left one (that is a finding: note the step).

## Section 5: hot reload keeps the table (all)

- [ ] **Steps:** with a session open, `touch` any file under the plugin's `hooks/` (or save it unchanged); wait for the next turn boundary; `Ctrl+]`, `?`.
- [ ] **Expected:** the debug log (`$CLAUDE_USER_DIR/bookmarks/debug/<session id>.log`) shows a clean reload; the help lists the same keys as before.

## Section 6: choosing your own keys in /config (A3, A6)

### 6.1 The rows are folded until you open them

- [ ] **Steps:** `/config`, type `bookmarks` in the search box.
- [ ] **Expected:** a row **Keys: show the key rows** reading `hidden`, and no other `Keys:` row.
- [ ] **Steps:** set it to `shown`, and watch the menu without closing it.
- [ ] **Expected:** fourteen rows appear under it at once: `Keys: mark` through `Keys: help`, `Keys: in a list`, `Keys: the leader`. Set it back to `hidden`: they go, again without closing the menu.

### 6.2 A key moves its button, its hint and its help together

- [ ] **Steps:** with the rows shown, set **Keys: prompts** to `l`. Close `/config`. `Ctrl+]`.
- [ ] **Expected:** the `prompts` button on the bar now presses with `l`; `?` lists `l` for the prompt list; typing `l` after the leader opens the prompts pane; `p` now gives the reminder of the keys.
- [ ] **Reset:** set **Keys: prompts** back to empty.

### 6.3 A clash and an unusable key are refused with the reason

- [ ] **Steps:** set **Keys: mark** to `j`.
- [ ] **Expected:** the menu refuses it with "j is already jump's key" (or the same in other words), and the row keeps its old value.
- [ ] **Steps:** set **Keys: mark** to `Up`.
- [ ] **Expected:** refused: "Up never reaches the band on a stock build".

### 6.4 `hidden` takes a button off the bar, and the key still works

- [ ] **Steps:** set **Keys: read** to `Space r hidden`. `Ctrl+]`.
- [ ] **Expected:** no `read` button on the bar; `Space` after the leader still goes to the reading position. Reset the row to empty.

### 6.5 The list keys follow their row

- [ ] **Steps:** set **Keys: in a list** to `n p`. `Ctrl+]`, `p`.
- [ ] **Expected:** the band's number row shows `n↓` and `p↑` instead of `j↓` and `k↑`, and `n` moves the `▶` down the list. Reset the row to empty.

### 6.6 The Leader row says where the leader is bound

- [ ] **Steps:** look at **Keys: the leader**'s help text; then try to set it to `ctrl+k`.
- [ ] **Expected:** the help names your chord (`Bound to ctrl+] ...` on the default setup); the change is refused with where to bind it (`~/.claude/keybindings.json`, `abovePrompt:focus`).

### 6.7 A value set by hand is named, not obeyed

- [ ] **Steps:** close Claude Code. Back up `~/.claude/settings.json`, then under `pluginConfigs` -> the plugin's entry (`bookmarks@...`) -> `options`, set `"keyMark": "Tab"`. Start Claude Code in the scratch setup.
- [ ] **Expected:** `m` still marks; the debug log (`$CLAUDE_USER_DIR/bookmarks/debug/<session id>.log`) has a `[bm] keymap: mark "Tab": Tab never reaches the band ...` line. Put the setting back.

### 6.8 The docs say what the menu does

- [ ] **Steps:** read `docs/keys.md`, "Choosing your own keys", and the README's Configuration rows.
- [ ] **Expected:** each step above is described there; nothing says the keys are fixed.

## What the automated tests DON'T cover

- The band as Claude Code draws it: hotkey markers, button order on a narrow terminal, the mouse click itself (the kit records a press, it cannot click).
- Hot reload of a live session and whether the table survives it.
- The real register file: its modified time, its text after `D`, a second session reading it.
- A terminal's focus and hover: where the keyboard lands after a button, what a hover highlights.
- `/config` as the person sees it: the fold repainting the open menu, a refusal's wording in the menu (Section 6).
- The wording of hints and help as read by someone new to the plugin.

## Reporting issues found

1. Note the section and step number.
2. Copy the band or pane as drawn (a screenshot or the text) and the debug log's last lines.
3. Keep the scratch register file.
4. File an issue naming this checklist and the version at the top.

## Cleanup

Set every `Keys:` row back to empty and the fold to `hidden` (or restore the `settings.json` backup from 6.7). Close the session; delete the scratch folder (`%TEMP%\bm-checklist`, `$env:TEMP\bm-checklist`, or `/tmp/bm-checklist`). Nothing under your real `~/claude/bookmarks` was touched if `CLAUDE_USER_DIR` was set before `claude` started.
