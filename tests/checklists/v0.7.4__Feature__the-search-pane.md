# Human Test Checklist: the search pane

**Target version:** 0.7.4
**Ships with commit:** TBD (`feat(search): the search pane, every row of the conversation (v0.7.4)`)
**Companion automated tests:** `tests/core/search-pane.test.ts` (16: the field's `#N`/`*N`, numbering 1 the newest, kind labels, toggles and views, steps, a newer keystroke mid-read, landing by the drawn id or by uuid with words, pins), `plugin/tests/search.test.ts` (10: opening from the band, narrowing, a toggle, steps and Enter, `#N` and the yellow row, `*N` pins a tool row, the view setting, the toggle row hidden, the two layouts). Red-green: 14 deliberate breaks of the search code, every one caught.

## What this is

This short checklist is the hand-run check of the search pane, the first visible 0.7 feature. The mocks can check what the pane draws and what a press asks for. They cannot check how typing feels in a live band, whether a scroll lands where a person expects in the TUI, how long the first read of a real conversation takes, or whether the highlight is visible. Run it in a live Claude Code session with the plugin loaded.

## Prerequisites

1. Claude Code with the plugin at 0.7.4 (`/bm-env` shows it), in a conversation with some prompts, replies and tool calls; a long one (tens of MB) for HV.1's reading line.
2. **Isolation (optional):** start Claude Code with `CLAUDE_USER_DIR` on a scratch folder, so the pins and the search's cached files stay out of your real bookmark folder:

   **cmd.exe**:
   ```cmd
   set CLAUDE_USER_DIR=%TEMP%\bm-check
   claude
   ```

   **PowerShell**:
   ```powershell
   $env:CLAUDE_USER_DIR = "$env:TEMP\bm-check"
   claude
   ```

   **POSIX**:
   ```bash
   export CLAUDE_USER_DIR=/tmp/bm-check
   claude
   ```

## High-Value Verification (~5 minutes)

### HV.1: opening search

- [ ] **Steps:**
  1. Press the leader (`Ctrl+]` by default), then `/`.
  2. Close it (`Esc`, then the pane's ×), then click the bar's `/search` button.
- [ ] **Expected:**
  - The band shows `search`, `↑`, a field labelled `/`, `↓`. The pane opens beside the conversation and lists every row newest first, numbered from 1, each with its kind (`you`, `claude`, `Bash`, `output`, ...).
  - In a long conversation the first open says it is reading the conversation, with progress, and fills in as it reads.
  - Clicking `/search` again with the pane open closes it.
- [ ] **Why this matters:** `/` has to reach the plugin from the band's field rather than start a Claude Code slash command.

### HV.2: typing narrows

- [ ] **Steps:** type a word that appears a few times; then try `"an exact phrase"`, `m/load(er|ing)/i`, `in:tools loader`, `loader -in:thinking`.
- [ ] **Expected:** the list narrows as you type, with no visible lag. The line under the toggles says how many matched of how many (`4 of 1,284 places`). An unfinished `m/foo(` says it is incomplete rather than matching nothing.
- [ ] **Why this matters:** per-keystroke search is the feature (#20).

### HV.3: moving and landing

- [ ] **Steps:**
  1. Press `Tab` twice (or click `↓` twice), then `Enter`.
  2. Reopen search, type `#5`, and watch the `▶` before pressing `Enter`.
  3. Land on a prompt or reply result, then on a `Bash` result.
- [ ] **Expected:**
  - The first step puts the `▶` on 1, the second on 2; `Enter` goes there.
  - Typing `#5` moves the `▶` to 5 before `Enter`.
  - The result you went to is drawn in yellow, with "#N = the result you last went to" under the legend.
  - A prompt or reply lands with its first line (or your search words) highlighted; a `Bash` result lands on the tool's row, or on the folded "Ran 1 shell command" line that holds it.
- [ ] **Why this matters:** a landing nobody can see happened is the bug that led to the yellow row.

### HV.4: pinning a result

- [ ] **Steps:** type `*3` and `Enter`; then `*3` and `Enter` again.
- [ ] **Expected:** a toast "pinned result #3" and a gold `★` in its number; the second time "unpinned". The band stays in search.
- [ ] **Why this matters:** a pin from search keeps a tool row's exact address, which the prompts list cannot pin.

### HV.5: the toggles and the settings

- [ ] **Steps:**
  1. In the pane, click `tools`, then `you`, then `all`.
  2. In `/config`, open **▸ Bookmarks**, then **▸ Search: show the search rows** (the search rows are hidden until it is open), and set "Search: what it opens on" to `you+claude+sessions+tools+outputs`; reopen search in a new conversation. Then set it to `custom`: nine "Search: custom includes ..." rows appear; turn `thinking` on and `claude` off, and reopen search.
  3. Set "Search: the row of toggles" to `hidden`, and "Search: how a result says what it is" to `short`.
  4. Click `claude` alone: replies show no `claude:` label, a thinking block still says `thinking:`; set "Search: labels in a one-kind view" to `always` and the labels come back. With "Lines per row in the lists" at 3 or more, a long reply fills its lines instead of stopping after about 160 characters.
  5. Turn on the `agents` toggle, then switch "Search: how a result is laid out" between `stacked` and `inline`; then set "Lines per row in the lists" to 1.
- [ ] **Expected:**
  - `tools` alone shows only tool calls; `you` adds your prompts; `all` brings everything back. A toggle you press stands while the conversation lasts.
  - The new conversation's search opens with `you`, `claude`, `sessions`, `tools`, `outputs` on; with `custom` as set, `you`, `sessions`, `tools`, `outputs`, `thinking`. The custom rows are hidden for any other choice.
  - With the row hidden there are no toggles (`in:tools` in the query still narrows); with `short`, rows say `yo:`, `cl:`, `ou:` and a tool keeps its name, while the toggles keep their words. "Search: letters in a short kind" appears; at 3, rows say `you:`, `cla:`, `out:`.
  - `stacked` (the default): a long kind such as `mid-engineer · SubagentHandback:` sits on its own line and the text starts a little indented below, using the pane's width, while `you:`, `claude:`, `Bash:` stay beside their text; `inline`: every text beside its kind. At 1 line per row both look like `inline`.
- [ ] **Why this matters:** the settings are how a person makes search open on what they look for.

### HV.6: /bm-search

- [ ] **Steps:** from an empty input box, type `/bm-search loader`.
- [ ] **Expected:** the pane opens already searching for `loader`.

## Section 1: edges

### 1.1 The bar's order

- [ ] **Expected:** the idle band's bar reads `mark  jump  read  prompts  /search  ?`. `?` lists `/` among the commands.

### 1.2 A result from before a compaction

- [ ] **Steps:** in a conversation that has been compacted, land on an old prompt result.
- [ ] **Expected:** a toast says it can't jump there, and that the prompt's first line was copied; `ctrl+o` then paste into its search finds it.

### 1.3 A thinking result (known gap)

- [ ] **Expected:** it lands on its message, with the thinking still folded (`ctrl+o` shows it). Revealing it from search is planned, not in this version.

## What the automated tests DON'T cover

- Whether `/` typed into the band's field reaches the plugin in a live session (settled live once, at 0.7.4's first look).
- Where a scroll lands in the real TUI, folded or unfolded, and whether the highlight is visible.
- How long the first read of a large conversation takes, and how typing feels while it runs.
- How the pane reads at narrow widths, with long rows and the toggle row wrapping.

## Reporting issues found

1. Note the HV or section number.
2. Copy what you typed, what the pane showed, and the `/bm-env` output.
3. File an issue referencing this checklist and v0.7.4.

## Cleanup

With isolation, remove the scratch folder (`dz safedel "%TEMP%\bm-check"`, or delete it by hand) and clear the variable:

- **cmd.exe:** `set CLAUDE_USER_DIR=`
- **PowerShell:** `Remove-Item Env:\CLAUDE_USER_DIR`
- **POSIX:** `unset CLAUDE_USER_DIR`

Without isolation, unpin anything HV.4 pinned (`*N` again), and set the three search settings back in `/config` if you changed them.
