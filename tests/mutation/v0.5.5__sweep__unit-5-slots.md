## Triage

- **M1, don't-care by the goal's own rule.** The cap's value is one of the three open format values djdarcy decides (goal 2026-10-16: "named constants with a question each in OPEN-QUESTIONS, never guessed into a check"); the tests use the constant's name, so a test that pinned 50 would be the guess the rule forbids. The constant's *application* (the history is capped at all) is pinned. Recorded in `equivalents.md`.
- **M4, killable.** With the mutant, any letter with a history "contains" any `n`, and the only wrong case the test tried (`n` 99) failed later anyway because no record 99 exists. A record that exists but was never under the letter (`n` 12, "twelve") now shows the difference.
- **M9, killable.** Every slot entry's time equalled its record's creation time in the fixture; a re-mark of the same message at a later time separates the two, and `markedAt` must be the later one.

## Caveats

A kill proves the suite noticed *this* change, not that it tests the right thing. **A clean sweep is evidence about the mutations tried, not proof of suite completeness.** The red-green audit of the unit's own tests (5 anchors / 1 guard, `scratchpad/redgreen/audit5.py`) is the separate check that those tests are attached to the change; the live check is the data root after the start (9 registers at v3 on this machine, 28 mark records, the store's `marks:` keys gone).
