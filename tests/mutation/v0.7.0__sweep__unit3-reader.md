## Triage

- **M14 was the important find.** Without the "already queued" check, a conversation that continues in another file re-queues that file every time the cursors run out, so the pass never ends; in a live session it would read the same file forever. The sweep did not hang only because no test had a continued conversation. The new test adds one, and the fake clock's drain is now bounded (500 ticks), so a pass that never ends fails instead of hanging the run.
- **M10 is also worth noting.** The earlier round-trip test asserted "another conversation is rebuilt", and passed through the later open-piece check rather than the session check. The new test passes the open piece, so only the session check can refuse it.
- **M6, equivalent.** `seal()` returns at once when the open piece has no lines, so dropping the `idx.open.bytes > 0` conjunct changes nothing.
- **M11, don't-care.** A short final chunk read as "not done" costs one more read, which returns 0 bytes and ends the file; the places and watermarks are the same. The cost is one extra program run per file.
- **M12, equivalent.** A stored output read in chunks instead of whole yields the same text.
- **M13, don't-care.** A stored output already kept is read again, and `addPlace` then refuses it as a duplicate; the cost is one read.

## Caveat

A kill proves the suite noticed *this* change, not that it tests the right thing, and **a clean sweep is evidence about the mutations tried, not proof of suite completeness.**
