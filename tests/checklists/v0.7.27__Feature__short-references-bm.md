# Human Test Checklist: short references (`bm:`), end to end

**Target version:** 0.7.27, covering the arc 0.7.16 to 0.7.27
**Ships with commit:** `docs(refs): short references in usage, the README and a checklist (v0.7.27)` (TBD at writing)
**Companion automated tests:** core `tests/core/ref.test.ts` (11: both forms, the tilde rule, the check, prefixes), `ref-resolve.test.ts` (13: this conversation first, the named one, every outcome), `ref-expand.test.ts` (4), `ref-binding.test.ts` (3), `anchor.test.ts` (16, the encoder among them), `item-links.test.ts` and `markers.test.ts` (+1 each), `record.test.ts` (+1); kit `plugin/tests/bm-refs.test.ts` (4: replies), `prompt-bindings.test.ts` (3: prompts), `tool.test.ts` (+3: the `ref` input, the answer's forms), `lists.test.ts` (+3), `note.test.ts` (+3). Every unit was red-green audited on a scratch copy.

## What this is

A hand check of the short reference across every place it now works: Claude's replies, your prompts, the bookmark tool, lists, notes and markers in your files. The kit has no transcript and no terminal, so it cannot show how a reply is drawn, what Claude actually received with a prompt, whether that survives a resume, how a hover looks in Windows Terminal, or whether a bookmark call stays quick on a long conversation. Those are checked here.

## Prerequisites

1. Plugin 0.7.27 or later loaded. Start or resume a session after updating: the bookmark and lists tools' inputs are read when the plugin starts.
2. A conversation (call it A) with at least two bookmarks. Ask Claude: "bookmark the message where we started, and the one where we decided X". Each answer carries `lookup`, `exact` and `cite`.
3. A second conversation (B) on this machine with at least one bookmark of its own. Note one of its references from its tool answer.
4. Nothing here edits your files except the scratch note in 6.1. To keep a copy of your lists first:

   **cmd.exe**: `copy %USERPROFILE%\claude\bookmarks\lists\*.json %TEMP%\`
   **PowerShell**: `Copy-Item "$env:USERPROFILE\claude\bookmarks\lists\*.json" $env:TEMP`
   **POSIX**: `cp ~/claude/bookmarks/lists/*.json /tmp/`

## High-Value Verification (~5 minutes)

### HV.1: a reply with five references draws each as a link (the live look)

Validates: replies expand `bm:` references, across conversations, leaving the transcript alone.

- [ ] **Steps:** in A, ask Claude to reply with exactly this text: three references to A's bookmarks (one as `[label](bm:...)`, one bare, one with `~w:words`), two into B (one lookup, one exact), and one made-up reference `bm:99999999/12345678`.
- [ ] **Expected:** the five real references are drawn as links (hover shows a `file:///.../bookmarks/sessions/...` address); a click on the three in A jumps there and highlights the words; the made-up one is plain text. A reference inside a code span stays text.
- [ ] **Check:** the transcript still holds the short text (`/bm-env` or the `.jsonl`: search for `bm:`).
- [ ] **Why this matters:** if replies do not draw them, short citations are unreadable and the citation trial cannot start.

### HV.2: a prompt is sent as typed, and Claude receives the binding

- [ ] **Steps:** type a prompt holding one `bm:` lookup from A and one pasted bookmark link, e.g. "what did we decide at bm:<sid8>.2~<check>?". Then ask: "quote the bm-binding note you received with my last prompt".
- [ ] **Expected:** the prompt in the chat reads exactly as typed. Claude quotes a `bm-binding v1:` note with one line per reference, each naming an exact `bm:<sid8>/<uuid8>` and, for the lookup, its record number.
- [ ] **Why this matters:** a short reference Claude has to guess is worse than none.

### HV.3: the binding survives a resume

- [ ] **Steps:** exit, `claude --resume` the same conversation, ask Claude again what was bound to that prompt.
- [ ] **Expected:** the same answer: the note is kept in the transcript with the prompt.

### HV.4: lists take a reference as a link

- [ ] **Steps:** ask Claude: "add an item to a list 'refs test' with link bm:<one of A's lookups>", then "add another with link bm:99999999.4~abcdef12". Open `/bm-lists`.
- [ ] **Expected:** the first item is drawn as a link and a press jumps to the place; the second is a plain item and a press copies `bm:99999999.4~abcdef12` (a toast says so). Neither is a file path.

### HV.5: a note spells out its references

- [ ] **Steps:** ask Claude to bookmark the reply from HV.1. Ctrl-click the link it returns.
- [ ] **Expected:** the note quotes the reply with each reference that resolved written as `[as typed](file:///...)`; its front matter reads `references: expanded 5 of 6` (the made-up one stays as written).

### HV.6: the bookmark call stays quick on a long conversation

- [ ] **Steps:** in a long conversation (thousands of messages) just after a restart, ask Claude to bookmark a message that holds a `bm:` reference to a tool call's output.
- [ ] **Expected:** the answer comes back within a couple of seconds, not after a long pause or an error; the note may say `expanded 0 of 1` for that reference.
- [ ] **Why this matters:** a note's references are looked up inside the bookmark call, which has 10 seconds in all.

## Section 1: replies

### 1.1 The words and the encoder

- [ ] **Steps:** ask for a reply holding `bm:<sid8>/<uuid8>~w:a%20phrase%20(with%20parentheses)`.
- [ ] **Expected:** drawn as one link; a click highlights "a phrase (with parentheses)"; the address in the hover has `%28` and `%29`, not bare parentheses.

### 1.2 A wrong check

- [ ] **Steps:** take a lookup from A and change its last character after `~`.
- [ ] **Expected:** drawn as text, not a link to some other record.

## Section 2: prompts

### 2.1 A slash command is untouched

- [ ] **Steps:** run `/bm-lists bm:<sid8>.1~<check>` (any local slash command with a reference in its arguments).
- [ ] **Expected:** the command runs as usual; no `bm-binding` note is attached to it (ask Claude in the next prompt).

### 2.2 A reference that does not resolve

- [ ] **Steps:** send a prompt with `bm:99999999/12345678`; ask Claude what it received.
- [ ] **Expected:** the note says that reference was not found (not on this machine), and Claude says so rather than guessing.

## Section 3: the bookmark tool

### 3.1 The answer's forms

- [ ] **Steps:** ask Claude to bookmark any message and show you the tool's full answer.
- [ ] **Expected:** `lookup` (`bm:<sid8>.<n>~<8 hex>`), `exact` (`bm:<sid8>/<8 hex>`), `cite` (`[label](bm:...)`), and the full `markdown` link.

### 3.2 A `ref` returns the existing record

- [ ] **Steps:** ask Claude to call the tool with `ref` set to that `lookup`.
- [ ] **Expected:** the same record number comes back, and the bookmarks pane gains no new entry.

## Section 4: lists

### 4.1 A reference that resolves later

- [ ] **Steps:** with the "refs test" list from HV.4, edit nothing; in conversation B (in the same project folder, since lists belong to the folder), press the first item.
- [ ] **Expected:** the press names conversation A and copies its `claude --resume` command (the place is in another conversation).

### 4.2 The page

- [ ] **Steps:** open the list's page.

  **cmd.exe**: `type %USERPROFILE%\claude\bookmarks\lists\<project>.md`
  **PowerShell**: `Get-Content "$env:USERPROFILE\claude\bookmarks\lists\<project>.md"`
  **POSIX**: `cat ~/claude/bookmarks/lists/<project>.md`
- [ ] **Expected:** the resolved item is a link; the kept reference is a plain line.

## Section 5: notes

### 5.1 A message with no reference

- [ ] **Steps:** bookmark a message holding no `bm:`; open its note.
- [ ] **Expected:** no `references:` line in the front matter.

## Section 6: markers in your files

### 6.1 Either form

- [ ] **Steps:** in a scratch Markdown file (outside any repo), write two lines: `- one [*](bm:<sid8>.<n>~<check>?list=refs-test&id=a)` and `- two [*](bm:<sid8>/<uuid8>?list=refs-test&id=b)`. Open it in Obsidian or your editor.
- [ ] **Expected:** both lines stay on one line each; nothing in the plugin edits the file. (The reader is checked by the core tests; lists that pick up file entries come later.)
- [ ] **Cleanup:** delete the scratch file.

## Section 7: the terminal

### 7.1 Windows Terminal

- [ ] **Steps:** hover each kind of link from HV.1 in Windows Terminal; repeat in a cmd.exe console.
- [ ] **Expected:** the hover shows the full `file:///` address; no mangled characters in the drawn text on either codepage.

## Known limits (not defects of this arc)

- Claude still writes the full link in its replies by default; short citations are being tried in practice first.
- A conversation that continues under a new session id (after some compactions or resumes) does not yet find its predecessor's bookmarks, and list items that name the old session id do not jump. That is the next fix.
- Copying text that holds a reference copies the short form as it is.

## What the automated tests DON'T cover

- How Claude Code actually draws a reply's links, and the hover
- What Claude receives with a prompt, and that it survives a resume (the kit has no transcript)
- Timing on a long real conversation (the kit's clock does not run the place reader)
- Two real conversations on one machine
- Windows codepages and terminal rendering

## Reporting issues found

1. Note the section and step number.
2. Capture the exact text typed and what was drawn (a screenshot helps for HV.1).
3. Attach the lines of `/bm-env` and the plugin log around the step.
4. File an issue referencing this checklist and the version from `/bm-env`.

## Cleanup

- Delete the "refs test" list (ask Claude: "delete the list refs test"; it is kept among removed lists, not erased).
- Restore the lists backup from Prerequisites 4 if you changed other lists.
- Delete the scratch Markdown file from 6.1.
