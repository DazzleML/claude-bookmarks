# Human Test Checklist: Pinned prompts, and leaving the leader

**Target version:** 0.1.6
**Ships with commit:** v0.1.6: pinned prompts; Esc leaves the band's key mode
**Companion automated tests:** none for these features. The 9 tests in `tests/test_version.py` cover repo tooling only (version and manifest). The plugin's own tests arrive with the core rebuild (#5). Everything below is checked by hand.

## What this is

A hand-run check of what v0.1.6 adds to the plugin:
- **pinned prompts** in the prompts pane (`*N`, `*`, `/bm-pin`, the **★ pinned** group);
- **leaving the leader's key mode** with `Esc`, typing, or closing the pane.

Both live in Claude Code's terminal UI and depend on keyboard focus, which no automated test here can drive. Run it before tagging, and after any Claude Code update that touches panes or the band.

## Prerequisites

1. **Claude Code 2.1.287 or later**, fullscreen renderer (`/tui fullscreen`).
2. **The plugin loaded** at v0.1.6: `/bm-env` reports `convo-bookmarks 0.1.6`.
3. **Test in a conversation you don't mind pinning prompts in**, ideally a fresh one: `claude` in a scratch folder, plus a few prompts sent ("one", "two", "three"…). Pins are stored per conversation, so they won't touch your other sessions.
4. **The leader key.** Claude Code's default is `Ctrl+X Tab`. If you've rebound `abovePrompt:focus` (for example to `Ctrl+]`), use that wherever this says "the leader".
5. **The debug log**, for the log checks. `/bm-env` shows the session id; the log is `<user dir>/bookmarks/debug/<session id>.log`, where the user dir is `CLAUDE_USER_DIR` if set, otherwise `~/claude`. To see its last lines:

   **cmd.exe**:
   ```cmd
   powershell -NoProfile -Command "Get-Content \"$env:USERPROFILE\claude\bookmarks\debug\<session id>.log\" -Tail 10"
   ```

   **PowerShell**:
   ```powershell
   Get-Content "$env:USERPROFILE\claude\bookmarks\debug\<session id>.log" -Tail 10
   ```

   **POSIX**:
   ```bash
   tail -n 10 ~/claude/bookmarks/debug/<session id>.log
   ```

**Reset between sections:** unpin whatever you pinned (`*N` again, or `/bm-pin N`), and press `Esc` or send a prompt to put the band back to its buttons.

## High-Value Verification (~5 minutes)

### HV.1: Pin the newest prompt from the pane

Validates: `*` toggles the newest prompt, the pane stays open, and the pinned look appears.

- [ ] **Steps:**
  1. With the input box empty, press `Ctrl+X p` (or the leader, then `p`).
  2. Type `*` and press `Enter`.
- [ ] **Expected:**
  - A toast: `pinned #N: <start of the prompt>`.
  - The pane stays open, with a **★ pinned** heading at the top listing that prompt as `N★) …`, and an **all prompts** heading above the full list.
  - In the full list, the same prompt reads `N★) …` with the star in gold; other rows read `N) …`.
- [ ] **Why this matters:** this is the feature: one keystroke to keep a prompt at hand.

### HV.2: Pin and unpin by number

Validates: `*21` toggles, and a second toggle removes it.

- [ ] **Steps:**
  1. In the pane, type `*2` (any prompt number) and press `Enter`.
  2. Type `*2` and `Enter` again.
- [ ] **Expected:** step 1 adds #2 to the pinned group (toast `pinned #2`); step 2 removes it (toast `unpinned #2`), and the pinned group disappears if it's empty.
- [ ] **Why this matters:** pins must be reversible, or the group fills with noise.

### HV.3: `/bm-pin` from the prompt

Validates: the command path, with and without a number.

- [ ] **Steps:**
  1. At the prompt, run `/bm-pin`.
  2. Run `/bm-pin 1`.
  3. Open `Ctrl+X p`.
- [ ] **Expected:** a toast for each; the pane's **★ pinned** group lists the newest prompt and #1, in the order pinned. Nothing appears in the conversation (the command answers silently).
- [ ] **Why this matters:** pinning without opening the pane is the quick path while working.

### HV.4: `Esc` leaves the leader

Validates: the band notices it lost the keyboard and closes the pane.

- [ ] **Steps:**
  1. With the input box empty, press the leader, then `j`.
  2. Press `Esc` and wait one second, without typing.
- [ ] **Expected:** the band returns to `bm: m: mark j: jump p: prompts r: read`, and the pane closes within about half a second. The log shows `band lost the keyboard (…): closing the pane`.
- [ ] **Why this matters:** before v0.1.6 the pane stayed open for 15 seconds, stranding you.

### HV.5: Pins survive a restart

Validates: storage per conversation.

- [ ] **Steps:**
  1. Pin two prompts.
  2. `/exit`, then `claude --resume <session id>` from a shell.
  3. Open `Ctrl+X p`.
- [ ] **Expected:** the same two prompts are in the **★ pinned** group, in the same order.
- [ ] **Why this matters:** pins you lose on restart aren't pins.

## Section 1: Pinned prompts in detail

### 1.1 Typing `*` doesn't jump

- [ ] **Steps:** open `Ctrl+X p`; type `*` and then `1`, slowly, without `Enter`.
- [ ] **Expected:** no jump happens while typing, even though `1` alone would auto-jump. `Enter` then pins #1.

### 1.2 Plain numbers still jump

- [ ] **Steps:** open `Ctrl+X p`; type a prompt number and press `Enter`.
- [ ] **Expected:** a jump, and the pane closes, as before v0.1.6. The auto-jump rule still applies: with 25 prompts, `3` jumps at once and `2` waits.

### 1.3 An out-of-range number

- [ ] **Steps:** `*9999` and `Enter` in the pane; then `/bm-pin 9999` at the prompt.
- [ ] **Expected:** a toast `no prompt #9999 (1-N)` each time; nothing pinned; the pane stays open.

### 1.4 `/bm-pin #12`

- [ ] **Steps:** run `/bm-pin #12`.
- [ ] **Expected:** pins #12, the same as `/bm-pin 12`.

### 1.5 Pin order

- [ ] **Steps:** pin #5, then #2, then #9.
- [ ] **Expected:** the **★ pinned** group lists 5, 2, 9 (the order pinned), not by number.

### 1.6 Dimmed pinned rows

- [ ] **Steps:** in a long, compacted session, pin an early prompt that shows dimmed.
- [ ] **Expected:** its number, its `)` and its text stay dim; the star stays gold.

### 1.7 Pinning from the leader's prompt field

- [ ] **Steps:** press the leader, then `p`; in the band's `prompt #` field, type `*3` and press `Enter`.
- [ ] **Expected:** #3 is pinned (toast). The band's field and the pane behave the same way.

### 1.8 Pins are per conversation

- [ ] **Steps:** pin a prompt here; in a different conversation, open `Ctrl+X p`.
- [ ] **Expected:** no **★ pinned** group there (unless you pinned something in that conversation).

### 1.9 Narrow pane, long prompts

- [ ] **Steps:** pin a long prompt that wraps in the pane.
- [ ] **Expected:** the number and star stay visible at the start of the row (they don't get squeezed out); the prompt wraps beside them.

## Section 2: Leaving the leader

### 2.1 `Esc`, then type

- [ ] **Steps:** leader, `j`, `Esc`, then type a letter straight away.
- [ ] **Expected:** the pane closes (by the check or by the edit, whichever comes first), and your letter appears in the input box.

### 2.2 Close the pane yourself

- [ ] **Steps:** leader, `j`, then click the pane's `×` (or press `Ctrl+X x`).
- [ ] **Expected:** the pane closes, and the band returns to its buttons at once.

### 2.3 Waiting doesn't close it

- [ ] **Steps:** leader, `j`, then wait five seconds without pressing anything.
- [ ] **Expected:** the pane and the band's letters stay; nothing closes while the band still holds the keyboard. (If it closes, the log's `band lost the keyboard (…)` line says why.)

### 2.4 The timeout

- [ ] **Steps:** leader, `j`, then leave it for 20 seconds.
- [ ] **Expected:** the band returns to its buttons after about 15 seconds.

### 2.5 Mark and prompts modes

- [ ] **Steps:** leader, `m`, `Esc`; then leader, `p`, `Esc`.
- [ ] **Expected:** both close the pane within about half a second.

### 2.6 Jump mode with nothing to jump to

- [ ] **Steps:** in a conversation with no marks and no reading position, leader, `j`, `Esc`.
- [ ] **Expected:** the pane stays until you type or 15 seconds pass. Known limit: with nothing on the band to focus, the plugin can't check the keyboard.

## Section 3: Regressions

### 3.1 The chords still own the keyboard

- [ ] **Steps:** `Ctrl+X '`, then a mark's letter.
- [ ] **Expected:** the jump pane takes the keyboard and the letter jumps, as in v0.1.5. The band doesn't switch to its key mode.

### 3.2 Leader jump still works

- [ ] **Steps:** leader, `j`, a mark's letter.
- [ ] **Expected:** the jump, then the pane closes and the band returns to its buttons.

## What the automated tests DON'T cover

- Keyboard focus between the band, panes and the prompt (the whole of Section 2)
- How the pane draws: the gold star, wrapping, dim rows
- Persistence across a real restart and `--resume`
- Toast wording and timing
- Different terminals and leader keys (Windows Terminal, macOS Terminal, iTerm2, Linux terminals, tmux)

## Reporting issues found

1. Note the section and step.
2. Copy the last 10 lines of the debug log (see Prerequisites).
3. Note the Claude Code version (`claude --version`) and the terminal.
4. File an issue on DazzleML/claude-bookmarks referencing this checklist and v0.1.6.

## Cleanup

Unpin the prompts you pinned for testing (`*N`, or `/bm-pin N`), or simply leave them: pins only affect the conversation they were made in. Nothing outside Claude Code's plugin storage is changed.
