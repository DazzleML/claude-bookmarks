# Human Test Checklist: the record format and where the data lives (0.5.1 - 0.5.12)

**Target version:** 0.5.12
**Ships with commit:** `feat(data): the data folder's README, a format beside the version, where things live (v0.5.12)`
**Companion automated tests:** 365 core tests under `tests/core/` (`register-file.test.ts`, `migrations.test.ts`, `register-ops.test.ts`, `note.test.ts`, `session-index.test.ts`, `check.test.ts`, `data-readme.test.ts` among them) and 103 kit tests under `plugin/tests/`, run with `node --test tests/core/*.test.ts` and `claude plugin test plugin`.

## What this is

The 0.5.x line moved everything the plugin keeps for you into one folder, `~/claude/bookmarks/`, in files that carry their own format number and migrate themselves with backups. Twelve small releases built it; three of them have their own checklists (linked below) for the migration, the marks and the Obsidian note. This one is the closing pass: the checks that only a person on the real data root can run, in about ten minutes, after the plugin has reloaded on 0.5.12. Nothing here is destructive; one section describes a reinstall and asks you not to run it unless you mean to.

## Prerequisites

1. Claude Code with the plugin at 0.5.12 loaded (`/bm-env` names the version), on a machine that has used the plugin before: `~/claude/bookmarks/sessions/` holds at least one conversation's bookmark file.
2. Obsidian for HV.2 (any recent version); without it, read `INDEX.md` in any Markdown viewer.
3. Nothing is changed by these steps except what the plugin writes on its own at a start or a save. Still, before you begin, copy the sessions folder aside once:

   **cmd.exe**: `xcopy /E /I "%USERPROFILE%\claude\bookmarks\sessions" "%TEMP%\bookmarks-sessions-before-0.5.12"`
   **PowerShell**: `Copy-Item -Recurse "$env:USERPROFILE\claude\bookmarks\sessions" "$env:TEMP\bookmarks-sessions-before-0.5.12"`
   **POSIX**: `cp -r ~/claude/bookmarks/sessions /tmp/bookmarks-sessions-before-0.5.12`

Reset between sections: nothing to reset; each section reads.

## High-Value Verification (~5 minutes)

### HV.1 -- `/bm-check` on the real folder

Validates: the linter over a real data root with real run folders.

- [ ] **Steps:** in Claude Code type `/bm-check`.
- [ ] **Expected:** a first line counting the register files and how many are at v3; one `backups:` line with the number of migration runs, all `done and intact`, and `1 snapshot(s)` (the copy taken before the first migration on this machine); a `store:` line well under the cap; `index.json lists N conversation(s) with bookmarks, matching the registers`; the last line `bm-check: nothing to report; nothing was changed`. No `WARN` line. If there is one, read it: each says what the next start or save will do.
- [ ] **Why this matters:** this is the one view of the whole folder's health; a warning here on a clean machine is a defect in the plugin, not in your data.

### HV.2 -- `INDEX.md` opens as a map

Validates: the generated index against a real set of conversations.

- [ ] **Steps:** open `~/claude/bookmarks` in Obsidian (Open folder as vault) and open `sessions/INDEX.md`; or open it in any Markdown viewer.
- [ ] **Expected:** `# Bookmarks`, a count of conversations, then a heading per conversation (its title, or the first eight characters of its id, with the project), newest first; under each a line per bookmark with its number, list and tier; each bookmark whose note exists is a link that opens the note; a bookmark without a note is plain text.
- [ ] **Why this matters:** the index is the folder's front door; a broken link or a missing conversation here is a wrong `entryOf` or a wrong note check.

### HV.3 -- The README is there and says what to back up

Validates: `ensureReadme` at a start.

- [ ] **Steps:**

  **cmd.exe**: `type "%USERPROFILE%\claude\bookmarks\README.md"`
  **PowerShell**: `Get-Content "$env:USERPROFILE\claude\bookmarks\README.md"`
  **POSIX**: `cat ~/claude/bookmarks/README.md`
- [ ] **Expected:** the first line is the plugin's marker comment, the second `<!-- writer: bookmarks 0.5.12 -->`; a table of every path with its kind (authored, backup, cache, generated); a "What to back up" section; the reinstall sentence. Open it in Obsidian too: it renders as a page.
- [ ] **Why this matters:** a person (or a backup tool's author) who finds the folder should not need the plugin's docs to know which files are theirs.

### HV.4 -- The `format` field arrives on the next save, with no backup folder

Validates: the field is additive, not a migration.

- [ ] **Steps:** count the folders under `~/claude/bookmarks/backups/`; open a conversation's bookmark file and note whether it has `"format"` (a file last saved before 0.5.12 does not); in that conversation make any change -- relabel a bookmark, set a mark; re-read the file and count the backups again.
- [ ] **Expected:** the file now reads `"version": 3,` then `"format": 3,` in that order; the backups count is unchanged; `/bm-check` still says nothing to report.
- [ ] **Why this matters:** this is the rule the field was added for -- track the format without forcing a migration or a backup when nothing needs one.

### HV.5 -- The earlier checklists still hold

- [ ] **Steps:** run HV.1 of `v0.5.4__Feature__register-format-v2-and-the-migration.md` (the migration's run folders), HV.1 of `v0.5.5__Feature__marks-in-the-register.md` (marks in the file), HV.3 of `v0.5.9__Feature__the-markdown-as-an-obsidian-note.md` (an edit in Obsidian read back).
- [ ] **Expected:** each as written there; nothing in 0.5.10-0.5.12 changed those paths.

## Section 1: the reinstall paragraph (read, do not run)

The docs say a reinstall under another marketplace name starts an empty plugin store and resets the `/config` options, while the bookmarks folder is untouched. This is **described here, not exercised**: reinstalling discards the prompt list cache and your `/config` choices on this machine. If you do mean to reinstall:

- [ ] **Steps:** note your `/config` choices for the plugin and the count of files under `~/claude/bookmarks/sessions/`; reinstall; open a conversation that had marks and bookmarks.
- [ ] **Expected:** the marks and bookmarks are all there (they live in the folder); the file count is unchanged; `/config` shows the plugin's defaults; the prompts list refills from the transcript.

## What the automated tests DO cover

| Area | Test file | Count |
|---|---|---|
| the format field: parse, serialize order, `newerThanBuild` by format, `formatOf`, migrations setting it | `tests/core/register-file.test.ts`, `tests/core/migrations.test.ts` | 2 tests extended |
| the README's text and when it is rewritten | `tests/core/data-readme.test.ts`, `plugin/tests/readme.test.ts` | 2 + 3 |
| the index, `/bm-check`, the note, the migrations, the guard | the files named in the companion line | 0.5.1-0.5.11's tests |

## What the automated tests DON'T cover

- a real data root: real run folders with real hashes, the real store's size, the real number of registers (HV.1)
- Obsidian's rendering of `INDEX.md` and of the README, and its following of the relative links (HV.2, HV.3)
- a file saved before 0.5.12 gaining `format` on a real save without a backup (HV.4)
- a real reinstall (Section 1)
- whether the folder reads as finished to a person who never read the docs

## Reporting issues found

1. Note the step (HV.n or 1) and what you saw against what was expected.
2. Keep `/bm-check`'s lines and the file in question as they were.
3. File an issue referencing this checklist and the version; attach the plugin's log lines starting `[bm]`.
